## 审查发现及修正后的复核

下表记录开发期间发现的数据安全问题及最终行为。优先级是本轮修复排序，不表示这些问题仍存在于上述提交中；独立反例使用合成目录与子进程，未对生产环境做破坏测试。

| 优先级 | 原触发条件与影响 | 修正及复核结果 |
| --- | --- | --- |
| P1 | 按 SQLite 文件头识别所有数据库并调用备份接口，重写了领域内容对象中的 SQLite 附件，导致对象 hash 失效 | 仅备份已知本机运行数据库；独立附件反例的原始字节和内容 hash 保持一致 |
| P1 | 新包清单只核对已列文件，空清单或遗漏文件仍可能通过 | 准备和应用时校验完整文件集合及 SHA-256；额外未列文件在切换前被拒绝 |
| P1 | 准备完成后，交接先启动 payload Python/helper，完整性检查可能晚于执行 | 启动前核验冻结包，并比较外置 helper 与包内 helper；被修改的 helper 不会被启动 |
| P1 | 回滚只覆盖仍存在的数据；升级后删除的工作区或配置会从旧安装复活 | 快照记录存在/删除状态，回滚重放删除；专项确认目录与配置不被复活 |
| P1 | 回滚准备直接修改保留的旧安装，中断可能留下部分覆盖的数据 | 使用单独回滚暂存目录和 `rollback_staging` 阶段，原旧安装保持完整；中断后可继续恢复 |
| P1 | 到达 `rollback_ready` 后中断，用户继续在新安装写入，再恢复会使用中断前快照 | 识别仍在目标位置的新安装，重新快照当前数据；独立实际 apply 夹具确认中断后新文件仍在当前工作区 |
| P1 | 同一安装的多个 apply/rollback/recover 可竞争同一暂存目录、重命名和 journal | 目标安装使用目录外稳定跨进程锁，锁内重新读取状态；并行操作被明确阻止 |
| P1 | 最后快照检查后，首次公共写入创建此前未出现的锁，写入已成功但升级后的工作区遗漏该值 | 增加工作区共享维护锁与升级独占锁，覆盖锁事务、数据库事务和设置写入；真实子进程写入在成功确认前被阻止，普通共享访问仍可并发 |
| P1 | 另一工作区首次操作同一用例表时，只共享自身工作区锁，不能与升级互斥 | 用例表锁同时共享实际表目录的维护锁；独立跨工作区首次 `mark` 被阻止，Excel 原始字节不变 |
| P1 | 用安装路径字符串前缀判断进程归属，可把名字相邻的另一安装选为停止对象 | 使用解析后的路径归属及明确进程身份；合成相邻安装不再进入停止集合，活动录制仍阻止切换 |
| P2 | 只复制文件会漏空目录；重建数据库文件可能把原权限改成当前 umask 对应权限 | 保留空目录并复制原数据库权限；独立反例确认 `0600` 保留 |
| P2 | 维护锁上下文将业务自身的权限错误误报为“升级中、尚未写入” | 仅翻译获取锁时的冲突，业务 `PermissionError` 原样保留 |

另外，真实 CLI/HTTP 专项验证 `prepare --stop-services` 先返回持久 journal，再由独立进程处理服务停止与准备，避免将启动收据和最终成功混为一谈。新增文件、桥接附件临时目录删除和后台停止不会让已准备的 payload 随调用结束消失。

故障验证包含：备份中写入、暂存刷盘期间写入、校验失败、目录切换中断、模拟目录占用、回滚暂存中断，以及重复恢复。断言检查当前可用目录和数据，而不只检查失败目录里仍存在某个副本。

## 维护锁与停写前提

新版公共数据入口共享维护锁，升级独占同一工作区锁；共享表还按实际表目录互斥。维护锁不把正常的多会话访问全部串行化。升级期间发生锁冲突时，操作明确失败，待升级完成后重试；不能把失败的写入计为已保存。

升级仍要求停止旧版本及外部写入方。旧代码、直接写文件的脚本或外部程序可能不遵守维护锁。备份前后、暂存刷盘后和旧目录移动后的指纹检查能发现已覆盖的写入窗口；它们不构成针对任意外部进程的全局文件系统事务。已发现变化时取消切换或恢复当前旧目录；不能据此承诺所有时序下的不合作写入都可无损继续。

自动停止仅针对归属明确的 autoSkill 服务和队列进程，不以删除任务来停调度，也不自动取消业务回放、录制或用户浏览器。宿主配置中未传给当前进程的外置目录需要显式列入计划；不能假定程序已发现所有人工维护路径。

## 三平台构建探针和验收边界

Windows x64、Linux x64、Linux ARM64 的构建结构探针检查独立 `autoskill-upgrade.py`、`package-manifest.json` 及相应包文件清单。清单覆盖包内文件与内容 hash，构建产物保留独立升级入口。这类探针验证打包结构和完整性合同，**不是三套正式发行包在目标设备上的安装、升级或浏览器验收**。

本轮边界如下：

- 23 项专项及独立 CLI 验收运行于 Linux x64 合成安装；Windows、UOS 和 ARM64 目标设备尚未完成本轮升级验收。Linux 上注入目录占用错误不等于验证了 Windows 文件系统行为。
- 独立 CLI 使用本机虚拟环境入口及现有浏览器路径，没有据此认证完整离线运行时、自包含依赖或全平台发行包。
- 升级后的 `doctor` 是静态检查，没有执行 `doctor --launch`。`completed` 不表示浏览器已启动，也不表示业务用例通过；浏览器和业务仍需在实际安装上验收。
- 文件和阶段记录使用刷盘与原子替换，平台支持时刷新目录；本轮只验证进程中断及模拟失败，未做物理断电、存储硬件故障或 Windows 文件系统故障注入。
- 回滚保留当前数据，但不能保证旧程序理解后来产生的任意新业务格式。旧安装、失败目录和快照保留供后续恢复，不自动清理。
- 合成版本间的数据保留与副本迁移通过，不能替代所有历史发行版本到 2.2.1 的兼容矩阵。
