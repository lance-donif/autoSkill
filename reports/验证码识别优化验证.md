日期：2026-11-12。本次最终方案保留原有已学习识别参数，采用 B583 推理图优化和自适应亮字颜色恢复。新训练权重的多条实验路线未通过验收，失败记录完整保留；没有把它们替换进产品。

新增恢复在固定独立合成集上的整串正确数为 **771→868/1,200（64.25%→72.33%）**；本机受控的完整识别中位耗时为 **16.79→14.42ms（2线程）**。这些数字描述本次数据和机器，不代表生产站点总体准确率。

- 先检测稀疏的全幅黑灰线，再用三个灰度层区分背景、线和文字。仅在字色、线色、背景色可明确分离且文字众数至少为 128 时恢复对比度，其他图片沿原路径识别。恢复后未识别出字符才用原张量再试一次。

公开来源分别保持 341/1040 与 7/12，总计 348/1052；外部总 CER 保持 17.719%。原模型与纯速度优化版在全部 2,252 张上字符串相同。候选实际恢复 270 张，所有角色均 0 异常、0 空输出；本轮未触发恢复空白后的回退。

本轮通过全部 16 项前瞻业务门槛。此前开发实验的“每个分组 CER 不得上升”条件曾因一张本来就失败的暗字图多错两个字符而拒绝亮字方案，该拒绝仍保留。新的验收以验证码完整字符串成功为主，要求六类整串准确率不退、整体提高、普通逐图不变、首位至少净增 6/240、总体 CER 不升及外部兼容保持；逐组 CER 继续完整报告。新协议发生在本轮任何种子、图像、标签、预测之前，详见 [前瞻注册](evidence/captcha-color-recovery/holdout-04/business-acceptance-preregistration.json)、[全部门槛](evidence/captcha-color-recovery/holdout-04/acceptance-result.json) 和 [独立完整报告](evidence/captcha-color-recovery/holdout-04/盲测报告.md)。旧实验未被改写为通过。

## 完整识别链路性能

比较对象为任务起点的旧代码及 be9 模型，与 B583 加新恢复代码的整个升级链路；不能把所有提速归因于颜色恢复。恢复本身需要额外计算。

固定 ABBA/BAAB 顺序，16 个独立进程，每种线程配置每个版本 4 blocks、每块 32 个固定开发输入。共 608 次真实 `solve`、608 次 ORT 调用，0 错误、0 回退。计时包含 PNG 解码、背景合成、恢复、预处理、全部推理及解码。独立复算与原始数据一致。

| 配置与指标 | 原始版本 | 最终链路 |
| --- | ---: | ---: |
| ORT 默认线程：warm solve 中位 | 19.468ms | 16.497ms |
| ORT 默认线程：warm solve P95 | 55.972ms | 52.486ms |
| 2线程：warm solve 中位 | 16.793ms | 14.425ms |
| 2线程：warm solve P95 | 23.059ms | 23.209ms |
| 2线程：process-cold 中位 | 142.331ms | 125.404ms |
| 2线程：process-cold P95 | 155.825ms | 222.363ms |
| 2线程：进程峰值 RSS 中位 | 151,188KiB | 85,238KiB |

2 线程典型整链路耗时降低约 14.1%，但 warm P95 略差，cold 也有尾部异常值，不能称所有时延均改善。Cold 每组只有 4 个进程样本，P95 等于最大值；不含解释器启动，不清空 OS 页缓存。运行环境为 Linux x64、约 2 核配额、Python 3.12.14、ORT 1.19.2、NumPy 2.0.2、Pillow 11.3.0。原始逐块数据及全部身份信息见 [受控性能结果](evidence/captcha-color-recovery/solver-benchmark/solver-pipeline-benchmark.json)，复现说明见 [完整链路基准](../training/captcha-research/BENCHMARK_SOLVER_PIPELINE.md)。
