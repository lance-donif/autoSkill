# Linux / UOS 平台支持验证

日期：2026-11-12。版本：v2.1.0。目标：Linux x64，以及使用者确认的统信 UOS 桌面版 ARM64（鲲鹏 / 飞腾等）。

## 实际完成

- CLI、DSH 插件按 x64 / ARM64 选择对应原生 Python、agent-browser、Chrome 和 chromedriver，不将 ARM64 当成 x64。
- `setup-linux.sh` 修复 ZIP 解压后的执行权限并配置浏览器。旧 UOS 可使用系统 Chromium 和主版本匹配的驱动；不会替换系统 glibc 或联网安装。
- `doctor` 显示发行版、CPU、glibc，拒绝错误架构和过旧 glibc；`doctor --launch` 检查二进制版本、驱动匹配并在本机示例页启动两种引擎。
- 三个平台分别原生组装 Release 包；全部临时附件的 size / digest 一致后，才删除旧同名附件并改名、发布。另附 SHA256SUMS.txt。
- 第三方官方支持范围与来源见 `docs/平台与第三方支持.md`。

## 开发环境结果

机器：Debian 13 x86_64，glibc 2.41，Python 3.12.14；浏览器为本机 Debian Chromium / chromedriver 156.0.8078.79，agent-browser 0.42.0。

| 检查 | 结果 |
| --- | --- |
| tests/test_linux_platforms.py | 6 项通过：架构、glibc、原生路径、驱动不匹配、系统浏览器持久化、错误 ELF 架构 |
| tests/test_platform_release.py | 1 项通过：第二个上传 digest 错误时保留全部原附件 |
| tests/plugin.test.mjs | 8 项通过：含 Linux 原生离线包运行时选择 |
| Python 编译、POSIX sh 语法 | 通过 |
| ARM64 依赖下载 | 42 个 wheels 实际下载成功，约 66 MiB，manylinux2014 / manylinux_2_28 |
| Linux 开发入口 doctor --launch | agent-browser --version 成功；Playwright、Selenium 均在本机示例页启动成功 |

本机已有源码 venv 和系统浏览器；上述结果**不等于新发布离线包启动通过**。发布构建只做导入、架构和归档校验，不启动浏览器，不跑完整功能回归（使用者明确要求跳过）。

## 未完成的验收

- 没有 UOS ARM64 真机，无法证明其特定系统版本、系统库、浏览器、DSH 已正常执行技能任务。
- Ubuntu 24.04 ARM64 原生构建仅证明包的架构和导入能在该 runner 运行，不能写成 UOS 已通过。
- DSH 默认沙箱智能体验收仍未完成；模型网关在当前环境被代理 CONNECT 403 阻断。
- 先前 Windows 独立 Selenium 导出脚本偶发停留初始空白页的问题，本次没有宣称修复。

包的最终大小、SHA-256、构建提交和附件链接在发布成功后由 CI 写入 `reports/offline-package.json`、`reports/release-status.json` 和交付验证报告第 1 节。
