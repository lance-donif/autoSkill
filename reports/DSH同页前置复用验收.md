# DSH 同页前置复用验收

2026 年 11 月 17 日，在 autoSkill 的对话式设计、回放和发布流程上补充同页前置。技能可以用 `record start <项目> --reuse <已有页面用例>` 执行保存的页面步骤。验证通过后，继续在同一标签页录制新动作和独立预期。新用例固定前置的编号、版本与内容哈希，回放时重建该页面状态。

## 真实 DSH

在独立验收数据目录使用 `deepseek-v4.1-flash`。父会话从 `/autoskill-use` 加载技能，起初启动了普通录制。收到同一对话的明确分工提示后，父会话把续测任务交给原生子智能体。子智能体先生成 14 列设计表，再调用 `--reuse` 执行旧用例 `TC-UI-003` v1，留下 Item #2 展开的可见窗口与通过回执。

录制接着该页面，只新增点击 Item #3。自动回放 `run-4a8b1eb4fb6b` 先执行固定版本的前置，再核验 Item #2 仍展开。点击 Item #3 后核验 #3 展开和 #2 折叠，三条检查均通过。新用例 `TC-UI-004` 已发布到 `Bootstrap / 组件 / Accordion / 展开互斥`，同一设计表的 14 列 Excel 已回填。录制和回放各观察到一个可见的 Chromium 窗口。[Bootstrap Accordion](https://getbootstrap.com/docs/5.3/components/accordion/)

父会话按确切运行编号复核了自动回放，原生 ToDo 写入次数为 0。随后通过「可复用用例」按目录手动回放新用例，`run-4a5bfed6b401` 使用同一个 v1 前置并通过。页面可下载本次运行报告。

## 回归结果

- 合成站点的准备按钮只通过页面内存启用后续操作，刷新页面会重置。复用前置后，录制和回放均执行了新增操作。发布后的用例分别通过 Playwright、Selenium 和两种独立回放脚本。后来更新源用例时，已保存的新用例仍准确引用录制时选定的版本。
- 让前置首条断言失败后，前置后续点击和新增操作均未执行。模拟前置完成后采集初始化中断时，状态保留通过回执，重复启动会要求先核对现场。执行结果里修改过的前置版本信息无法通过回执校验。
- Python 执行、发布、录制、窗口和导出相关回归通过 65 项。Node 宿主检查含真实 DSH SDK，通过 82 项。可见窗口专项使用 X11 检查实际 Chromium 进程。

## 对话开销

技能对增量需求直接使用对话里已核实的用例编号，按需读取设计规则。轮询时使用 `run-status --brief`，保留运行状态、发布回执与报告入口。对本轮回执 `run-4a8b1eb4fb6b`，完整和简短响应分别为 5,645 与 1,585 字节，减少 71.9%。这是单次状态输出的体积对照。整轮模型 Token 用量尚无同任务对照。

同页前置适用于有独立断言的同项目单标签页用例，可沿用项目登录。带其他依赖或跨标签页的场景继续由现有工作流执行。

附件 `autoSkill-dsh-reuse-evidence.zip` 包含设计和回填后的 Excel、DSH 会话摘要、可见窗口截图、自动与手动回放回执及回归日志。
