# 状态分类与联动优化报告

本轮已完成状态协议、后台状态推进、接口及页面联动、报告恢复和盲测发现问题的修复。接口、列表、详情、统计和宿主摘要使用同一个状态投影。当前候选以`c11671395ec4424d98fe5628f61350105a5c6e3d`为基线，生产源码和测试在最终全量期间保持不变；文件指纹见[开始快照](证据/checks/source-before-final-suite.json)和[结束快照](证据/checks/source-after-final-suite.json)。这些是本工作区的修改，版本号仍为2.2.4。

## 状态如何归类

| 状态维度 | 实施规则 |
| --- | --- |
| 生命周期、执行阶段 | 主状态表示排队、执行、等待宿主、等待执行、恢复、暂停、结束、取消；不能用Pass/Fail代替阶段。 |
| 综合结果 | 独立表示pending/pass/fail/blocked/cancelled/unverified。 |
| 业务、性能、质量 | 三个分项分别判断；正确答案超过声明SLA时可以业务通过、质量通过、性能失败、综合失败。 |
| 证据 | 核对冻结输入、真实尝试收据、原生outcome及附件；观察、无独立预期或失效证据不能支持当前通过。 |
| 报告 | 生成状态独立；ready要求Excel、简报、Bug清单均通过哈希和读回核验。 |
| 投递 | 宿主接收、投递成功独立；投递完成不能证明工作流或业务完成。 |
| 范围和历史 | 默认当前周期；显式读取历史，保留旧失败、重试及各次报告。当前输入变化使current=false并保留historical_outcome。 |

原始status和conclusion继续保存历史事实。较早业务失败不能被后来成功、取消或环境阻塞抹去；例如生命周期可以取消而综合结果仍保留失败。当前证据失效时不再计为当前通过。详细字段见[状态契约](../../skills/autoskill/references/state-contract.md)。

## 实施变更

1. `task_state.py`集中投影运行、用例、工作流、报告与投递状态。列表筛选在分页前执行，统计复用同一范围和核验结果。
2. 后台协调器每200ms处理确定性转换；状态GET不领取工作、不运行用例、不导出报告。未知副作用进入调查，租约令牌阻止旧提交。
3. 前台及宿主会话每250ms读取轻量版本，变化后获取新快照；保留筛选、草稿、原输入节点、焦点、选区和滚动。宿主代理保留完整state及会话边界。
4. 项目索引使用条件UPSERT。重复读取不重写业务行、创建时间、归档时间或状态版本；外部修改断言、需求来源和配置仍会触发刷新。
5. 同一次响应共享SQLite读取快照和证据投影，结束后清空。跨请求proof缓存绑定实际读到的内容及文件metadata；核验前后文件变化时不写缓存。读后并发替换outcome的确定性探针已通过，后续3次请求均降为invalid/unverified。
6. 首页`/api/dashboard`一次返回汇总、最近运行和失败列表，完整数据一起渲染，消除四次请求的重复验证及串行等待。
7. 工作流先冻结报告快照再异步生成。取消后恢复使用新报告代次，旧标识、快照和三件套字节保留。导出进程中断与并发等待不触发自动重试；run/recording/workflow失败都支持显式手动重试，业务请求数不增加。
8. 原生资产重跑使用原冻结版本和参数。页面提供“重跑原生资产”，不把原生结果冒充可选择的规范用例子集；旧失败运行保持不变。
