## 阶段改动

- **P0 · `b40422e`**。将 Windows 的结构体、指针类型、DLL 与函数签名移到模块初始化，覆盖锁、文件变更时间、DPAPI、进程和 Job 句柄、DACL。POSIX 的原子重命名绑定也只加载一次。按名称取得的线程锁改为弱引用。同步回收已退出的队列、报告、录制和运行子进程引用。插件通过 stdin 管道让 Python 看板正常退出，宿主崩溃时管道同样关闭。独立任务继续按现有持久化契约执行。
- **P1 · `6867b66`**。每轮调度按需复用一条 SQLite 连接与共享维护锁，保留各操作自己的提交与回滚边界。以索引判断运行、排队、删除和到期任务，用状态版本唤醒复核。计划、用例、运行结果批量读取。状态探活只做轻量读取。版本查询支持 ETag 和 HTTP 304，页面入口使用 `no-store`，内容哈希资源长期缓存。可见页保持 250 ms 刷新，隐藏页暂停，回到页面立即读状态。
- **P2 · `0cc0fec`**。精简离线资源和打包后的 wheel 内容。同步文件复用已验证的摘要，首次或文件变化时以流式 SHA-256 核验。闲置且 SQLite WAL 达到 64 MiB 时，最多每分钟执行一次被动检查点。同步失败暂存目录须由本程序标记、超过一小时且原进程已结束才清理。DSH 投递日志须有持久化确认且超过七天才清理。浏览器短路径目录只存放别名，录制和双引擎回放沿用原关闭与错误释放路径。
- **验证期间修整 · `ed6dc6d`、`8057eab`**。补齐慢启动测试的运行前检查夹具，保留原断言并增加请求顺序断言。去掉两条新增的静态检查告警。另补齐 `/api/dashboard` 最近记录的 `workspace_identity`，使其通过与 `/api/runs` 的同源范围校验。
- **抽屉焦点复验 · `334673e`、`f32ec34`**。保存当前控件的逻辑标识与弱引用。关闭抽屉时可恢复到刷新后的同一条用例，保留滚动位置。回归先确认新增目录已显示，再强制等待原控件离开页面，最后关闭抽屉。

看板最多追踪 8 个数据目录、每个最多 4,096 个证据路径。超出时以 500 ms 周期重新核对，保证旧证据的改动仍会刷新。DSH 前端会话可以回收已离开的视图，未决或核对中的操作仍能恢复。现有投递、业务结果、报表、录像和用户文件保留各自的生命周期。
