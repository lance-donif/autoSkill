# 录制转对话与压测验证

验证日期：2026-11-13。目标为本机 Ticket Desk 合成工单与固定销售数据，使用已安装的 Chromium、agent-browser、Playwright 和 Selenium。问数页面以确定性计算模拟对话，不调用外部模型；本报告不代表真实模型准确率或生产系统容量。

## 实际完成的闭环

页面实际登录 → 页面连续提问 → 录制器保存真实网络来源 → CLI 创建多轮资产 → CLI 单对话回放 → CLI 并发回放 → 故意错误与修复验证。

页面依次提问“2025 年销售额是多少？”与“北京呢？”。独立预期是固定数据的 700 与 200；预期在构建资产时明确提供，没有从已观察响应自动学习答案。HTTP 与 SSE 两种响应方式分别完成以下验证：

| 场景 | 真实执行结果 |
| --- | --- |
| 页面两轮对话 | 700 → 200，通过页面断言 |
| CDP 捕获 | 保存实际请求 Cookie、JSON 请求体、响应正文与每轮会话标识 |
| 单对话接口回放 | 两轮通过，后续请求使用服务端返回的 conversation_id |
| 并发回放 | concurrency=3、iterations=6，共 12 轮通过，确认 6 个不同 conversation_id |
| 打开 wrong_answer 合成故障 | 原资产判 Fail |
| 关闭合成故障 | 同一 asset_version 恢复 Pass，预期未修改 |

构建和回放使用真正的 CLI 子进程：`conversation build`、`native run --wait`。并发参数通过 JSON 输入；这证明页面捕获结果可直接用于后续接口和并发运行，未另写绕过来源的请求模板。

## 来源保真与并行隔离

原始 HAR、CDP 标准化证据和 CDP 事件分别归档为 `source.har`、`source.cdp.json`、`source.cdp.jsonl`，不把补采内容伪写进原 HAR。CDP 观察器读取同一次浏览器请求，未重新发送对话请求。

真实页面测试曾暴露原 HAR 缺少 Cookie 与 SSE 正文。修复后，Cookie 来源明确为 `requestWillBeSentExtraInfo`；SSE 字节来源明确为 `streamResourceContent`。页面在收到 done 后取消 reader 时，浏览器可能报告 loadingFailed；已捕获的字节、done 事件和取消状态分别保留，不因取消清空正文，也不凭 HTTP 200 宣称业务正确。

独立专项实际验证了新标签页、主标签页导航和刷新：3 个真实请求分别归属 2 个 target，正文与认证信息没有串用。两个具名会话同时录制时，取消 A 后 B 仍完成 SSE 提问、断言和归档；观察器进程、目录与录制状态分别独立，临时网络文件在成功归档或明确取消后清理。

## 断言与工单验收

- 失败的现场 check 持久保存声明期望、实际值与判定；以后修复业务并回放通过，也不改写原失败记录。
- 已观察到的业务 Fail 不会被后续缺凭据或环境中断清空；中断原因独立保存。
- 没有业务断言的历史动作仍可执行，业务验证度为 unverified。HAR 自动形成的规则标记为 observation，不当成独立需求预期。
- 支持单条断言等待时间、来源状态、连续成立窗口及持续不变量。两种浏览器和独立脚本共用判定函数；采样不能保证捕捉采样间的瞬时变化。
- Playwright、Selenium 和导出脚本均实际完成 Ticket Desk 创建、查询、解决和删除。high 被故意存成 medium 时判 Fail；修复后原断言 Pass。删除后的 `min_count=0` 正确通过。
- 标题上限从实现的 80 改为 40、需求仍为 V1 时，80 字接受用例失败。只有使用明确的 V2 需求预期，才验证 40 字接受、41 字拒绝；V1 预期和失败记录保留。
- Postman 动态期望保留提取变量类型；缺少变量表现为运行配置错误，不在业务断言里偷偷比较占位文本。导出文件说明首个失败停止、动作定位候选、验证码及登录历史管理的语义差异。
