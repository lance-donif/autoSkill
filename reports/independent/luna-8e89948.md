# autoSkill 独立测试报告

测试范围：仅检查当前目录内的 `SKILL.md`、安装入口、运行代码和测试代码；没有读取旧报告或其他工作目录。未安装/下载依赖、未访问公网、未修改生产系统，也未改动待测源码。临时验证项目与运行数据位于 `luna-probe-run/`。

## 结论

**按当前提交目录直接交付，无法满足“Windows x64 内网、离线即用、依赖随 Skill 提供”的使用条件。** 主 SKILL 写明依赖应在 `skills/autoskill/vendor/windows-x64/`（`skills/autoskill/SKILL.md:10-14`），但此目录在副本中不存在，`run-windows.cmd` 检查不到随附 Python 后会以退出码 2 停止（`skills/autoskill/run-windows.cmd:3-8`）。本次环境是 Linux x64，未执行 Windows CMD；这是按入口条件和文件清单得出的静态结论，不冒称 Windows 实测。

可用当前宿主已有的 Python/Node 依赖验证部分脚本/API 工作流与调度后台：需求关联、用例保存/校验、只读 API 执行、Excel/报告输出及任务创建/查询均有通过证据。但 UI 真实浏览器执行、AI 生成、Windows 离线入口和真实 DSH 宿主插件未能验证；没有把模拟用例或契约测试记为这些功能通过。

## 可复现问题与阻塞项

### 1. Windows 离线入口所需完整包没有随当前目录提供（阻塞）

- **预期：** 按主 SKILL 指示直接运行 `skills/autoskill/run-windows.cmd doctor`，检查随附 Windows Python、Node、浏览器和依赖；执行 `qa` 时不需联网初始化。
- **实际：** 当前副本不存在 `skills/autoskill/vendor/windows-x64/`，也未找到 `assets/`、`agent-browser-core.offline` 目录。CMD 第 4-6 行检测不到 `python/python.exe` 后立即返回 2；因此命令不会到达 `windows_entry.py`。Windows CMD 未在 Linux 上执行，故退出行为是按源码分支推断。
- **证据：** 文件清单中无上述离线目录；`run-windows.cmd:3-8`；`skills/autoskill/scripts/windows_entry.py:8-21,27-41`。`scripts/build-windows-bundle.py:40-87` 需要另行提供 `--assets`，组装 Python/Chrome/Node/wheels/SDK 及离线 Agent Browser；本次副本无这些资产。其产物清单还明确写 `windows_execution_verified: false`（该脚本第 94-100 行）。
- **影响：** 目标用户不能按 Skill 的首选离线入口启动。仅有源代码和命令文件不能替代预装运行时。

### 2. 安装指南与“不可联网初始化”的内网约束冲突（阻塞）

- **预期：** 用户把完整 Skill/插件包带入内网机器后即可运行，不需要 pip、npm、浏览器下载或在线获取 Skill。
- **实际：** `plugin/INSTALL.md:7-22` 要求 `pip install -r requirements.txt`、`playwright install chromium`、`npm install`，并介绍 `npm install -g agent-browser`、`agent-browser install` 和 `agent-browser skills get core`。这些命令需要提前准备外部依赖，与离线运行前提不相容。主 Skill 的 `skills/autoskill/SKILL.md:12-14` 则要求不运行这些下载命令，二者给首次使用者相互矛盾的入口指引。
- **影响：** 首次接触者可能按安装指南进入无法联网的依赖安装流程；若按主 Skill 直接运行，又会遇到第 1 项缺少 vendor 包而阻塞。

### 3. AI 生成与真实 UI 回放在本次环境受阻（未验证，不是通过）

- `node scripts/doctor.mjs --ui` 与 `--ai` 均返回 `ok: false`：Playwright Python 包存在但没有浏览器可执行文件；`agent-browser` 与 `@deepseek-ai/dsh-sdk-client` 均未安装，SDK API 检查为 false。`node scripts/agent-browser-offline.mjs --help` 实际输出 `Bundled Windows Agent Browser is unavailable; no download attempted` 并返回 2。
- 因没有 DSH 宿主、SDK/provider/model 和审批配置，本次没有调用模型生成用例或声称完成 AI 回放。因没有可启动浏览器，本次没有真实 UI 回放。
- 对 Windows 离线包本身也无法做平台验证；组装脚本产物模板明确标记 Windows 执行未验证（`scripts/build-windows-bundle.py:94-100`）。

## 使用范围判断

- **脚本/API 与数据留存：** 当前开发环境下的局部工作流可用；这是对本地合成用例和本机 API 的实测。
- **Skill 根据真实需求生成 UI/API 用例：** 未实测。项目存储可接受完整 JSON 用例输入，但本次以手写合成 JSON 测了保存和生成项目 UI/API Skill 的流程；AI 生成依赖 DSH SDK/provider/model。
- **无需模型脚本执行：** API 路径经本机合成服务实测；UI 路径未实测，因为缺少浏览器二进制。
- **DSH 仪表盘与定时任务：** 后台路由及任务创建/查询经 TestClient 验证；真实 DSH 侧栏、iframe/页面交互、插件启停和定时任务到期执行未验证。
- **更新/遥测：** 源码在子进程设置 `DO_NOT_TRACK`、关闭若干 npm/PIP 更新检查，Agent Browser 包装器也阻断安装/更新命令（`plugin/index.mjs:40`、`scripts/agent-browser-offline.mjs:9-24`）。主 Skill 同时说明 DSH 宿主自身遥测/更新仍须由管理员设置，不能据此保证整个宿主进程零外联（`skills/autoskill/SKILL.md:14`）。

## 首次使用建议

在向目标用户交付前，至少需要提供并校验一个完整 Windows x64 离线发行目录（包含脚本要求的 vendor 运行时、Python wheels、浏览器、Node 依赖、离线 Skill 指南及清单），让安装说明与该离线入口一致，并在 Windows x64 无网环境实际执行 `doctor`、脚本/API、UI 回放及 DSH 插件宿主验收。本报告不把这些尚未完成的项目记录为已通过。
