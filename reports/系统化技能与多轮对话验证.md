## 实际验证方法

多 agent 分别负责领域资产、workflow、执行证据、录制、CLI/宿主适配与发布；交叉检查时核对真实服务返回及持久回执，不采信执行方单独声称“已通过”。验证包括真实 Linux 浏览器、HTTP/SSE/WebSocket 请求、原生子进程、CLI 经 bridge 的调用，以及 SDK 形状的 DSH 替身。

测试目标主要是本机合成工单站点和冻结销售数据。这能证明错误处理、版本绑定、会话隔离和协议行为；不能据此声称真实模型准确率、生产容量或 Windows/UOS/DSH 新功能真机通过。真实 HTTP/CLI 不等于真实 DSH 模型驱动的自主 workflow。

## 自然提示词与独立多轮判断

外部验收位置：`/workspace/autoSkill-release/acceptance/dialogue-natural-20261113/`。由宿主 agent 通过真实 CLI 的 judge 租约/提交服务处理冻结请求，目标是本机实际 HTTP 服务。另一个 agent 独立请求并复核“重复询问地区”的反例。不是被测目标自评分，也没有声称真人参与者盲测或外部模型基准测试。

| 场景与自然问法 | 真实后续行为 | 完整 case 结论 |
| --- | --- | --- |
| “帮我算一下销售额，给个准确数字就行。”；冻结用户事实有北区、2025 年 | 目标先问地区，再问年份；judge 两次判断反问必要，分别自然回复已有事实；第三轮返回 100，独立数据为 40+60 | 1 条 case、3 轮，Pass |
| “帮我算 2025 年北区销售额，范围已经明确了，直接给金额。” | 目标仍问地区；judge 判断相关但不必要、已回答，Fail 后继续；下一轮正确返回 100 | 2 轮分别 Fail、Pass，整条仍 Fail |
| “帮我算 2025 年北区的销售额。” | 目标询问喜欢什么颜色；judge 判定离题 | Fail |
| “算下销售额，地区和年份我还没想好。” | 目标问地区；没有可引用用户选择，不编造回复 | 请求完成，但业务 Unverified / needs_clarification |

共 4 条计划 case、7 轮真实 HTTP 请求、7 份独立持久 judge 回执。验收断言均符合预期：1 条质量 Pass、2 条故意反例 Fail、1 条 Unverified。输出中的 `quality_pass_rate=0.25` 是这组刻意构造样本的通过比例，**不是模型准确率，也不是系统稳定性**。交互评审等待计入本次总耗时，因此不将该耗时和本地毫秒级响应分位数发布为性能基准。

补充合同已经覆盖：

- reply 为自然语言，`facts_used` 必须引用冻结 context/userfacts/reference，记录来源 hash；核心验证出处，语义正确性由独立宿主评审承担。
- 即时响应的既有断言失败不能被 judge 改成“合理澄清”后消失。只有显式 `expected_phase="final_answer"` 或 `when="final_answer"` 可在澄清轮暂缓。
- 缺宿主或评审超时保存待处理请求与回答证据，不自动判 Pass；异步原生运行使宿主能够继续处理自己的 judge 工作。
- 必要反问、重复反问、离题、未知事实分开判断；不能只判断回答流畅或采信目标自称“正确”。

## 真实录制、接口回放和原生执行

[录制转对话与压测验证](录制转对话与压测验证.md)记录另一条独立闭环：Ticket Desk 页面真实登录、提问“2025 年销售额是多少？”和“北京呢？”，显式独立预期为 700、200；CDP 保存同次请求的来源，CLI `conversation build` 构建资产，再由 `native run` 执行。

HTTP 与 SSE 分别完成：单 case 两轮通过；`concurrency=3`、`iterations=6` 共 12 轮，6 个不同服务端 conversation_id；打开 `wrong_answer` 故障后 Fail，关闭后相同 asset_version 恢复 Pass。没有把错误响应学习为新 oracle。捕获补采来自原请求，不为取得正文重新发送业务请求。

Ticket Desk 创建、查询、解决、删除在 Playwright、Selenium 及独立导出脚本中实际执行。`high → medium` 故障判 Fail，修复后原断言通过；标题限制从 80 改为 40 时，V1 期望先失败，只有来源明确的 V2 才建立 40 接受/41 拒绝的新预期。该报告保留了 7 项真实 UI/API 综合、7 项 capture、9 项断言证据等专项记录；新增 CLI 对话后半段单独通过，未把单项重跑说成整套再次通过。

原生工具实际运行了 unittest、Selenium pytest/POM、Newman、Apifox 和 JMeter 的正反例，保留原目录、参数化、fixture、脚本断言和原生报告。JMeter 实际产生并发请求和 JTL/HTML 证据；这不是用串行 HTTP 循环冒充压测。主流程一次 native 专项的 Selenium 因缺少浏览器环境变量跳过，随后补齐变量后单项通过；最终提供全部原生运行时的 486 项整体回归通过，无跳过。原生 CLI 单独安装，不表示发行包自带这些第三方工具。

原生执行的成功退出码不掩盖原生报告失败；没有声明业务断言的测量不冒充业务已验证。文件纳管也不等于任意框架被自动转换成语义等价的 UI IR。当前 workflow 候选发布针对 UI/API IR，原生资产由 native 服务及调度纳管，未将任意原生资产自动接入全部 workflow 阶段。

本轮 Windows 和 UOS 未做实机全链路验收。既有 Windows 包、Linux x64 浏览器和旧 DSH 页面历史证据各自保留原范围；Linux 专项通过不外推为 Windows/UOS 或实际生产模型通过。
