# 完整数据目录与 DSH 验证（v2.2.4）

日期：2026-11-13。环境：Linux x64、Python 3.12.14、Node 24.22.1、真实 Chromium 和 DSH 0.2.2-rc.1。此报告区分数据迁移、界面、SDK 和远端模型的验证范围。

功能提交：`c7004c0`。244 个受检源码/测试/配置文件已逐一与提交中的字节核对一致；旧升级模块与入口文档确实不在 Git 树中。随后仅补充验证记录，发行构建提交由 Release 记录给出。

## 程序与完整数据分离

删除 `upgrade` 命令、升级 HTTP 接口、独立升级器和打包复制入口。默认数据根为 Windows `%USERPROFILE%\autoSkill-data`、Linux/UOS `$HOME/autoSkill-data`，显式 `workspace` 配置优先。用例表、凭据、保存登录、知识、工作流、调度、历史、证据、三份报告和界面偏好均由该数据根保存。以后只替换程序，继续选择同一数据目录。首次迁入旧数据与分享完整 ZIP 通过内置数据管理完成，不替换程序，也不自动切换正在运行的服务。

新内部路径使用数据根相对引用。旧绝对路径通过明确的历史根和映射解析到当前副本；旧截图、报告、冻结输入和原生结果保持原始字节与哈希。复制后，旧进程号和投递令牌不授权新机器继续执行；未知业务效果进入恢复调查，已有 Fail 不擦除，也不自动补做旧操作。未来定时规则保留，已过期发生项不重复补发。

源和目标不混用：导入复制到空目标，冲突时原目录不覆盖；完整快照使用维护锁、SQLite backup、前后清点和逐文件哈希。普通整目录 ZIP 支持平铺与单顶层目录，手工压缩前需停止写入。数据库快照、文件系统发布与外部业务调用不宣称跨系统事务或外部“恰好一次”。

## 发现的问题与修复后结果

独立审核首次发现目标目录竞态可能删除新文件、桥接路径映射残留传输临时目录、冻结数据库与稍后读取的用例表依赖不一致、合法 Linux 文件名及目录权限往返不完整。修复后重跑原探针及新增场景全部通过：发布使用不可覆盖的目录重命名；依赖来自已冻结数据库；旧路径按原调用位置登记；权限、空目录、不可变 SQLite 资产和 WAL 已提交数据均核对。初次失败证据未覆盖。

运行恢复专项还检验了四个真实进程强制退出点：日志、数据库提交、首个控制文件归档和位置标记。恢复复用原事件，不重复修订或发出业务请求；部分执行已失败的工作流仍保留 Fail，旧 outbox token 不能继续确认。当前执行归属用机器、数据位置和进程出生信息共同判断。

联测时一个旧测试仅手工写入 Running/pid、缺少现行归属字段，触发正常的“无归属运行”恢复，随后被该 fixture 自己持有的证据锁阻塞。诊断日志和中止记录保留；修正 fixture 为真实活跃执行器身份，未减弱原等待/跳过断言，关联 43 项随后通过。UI 联测也修正了同 hash 导航不重载与创建项目字段写错的两个测试刺激问题。本报告的通过数不是首次尝试稳定率。

首次全项目回归运行 696 项、573.383 秒，2 项失败、0 错误、0 跳过：分享包测试的全部内容/凭据/登录断言通过后，最后仍把默认数据根与旧安装内路径比较；旧进程恢复测试仍匹配“意外结束”，实际已正确返回 Blocked 和“未自动重放”。随后将默认路径 fixture 隔离到临时 HOME/USERPROFILE，并让退出提示检查现行语义和零结果；另隔离一个只读 ARM 路径 fixture，避免读取真实用户配置。首次运行误落到 HOME 的合成 fixture 已完整移入私有证据目录，未删除。首次运行期间仅兼容性文档变化，应用、脚本及测试字节未变化。

后续复核发现真实调度缺陷：完整数据导出持有维护锁时，独立调度器的初始化、待执行检查或空闲退出锁可能抛错退出，未来定时定义仍启用却无人执行。真实子进程和三个受控窗口均复现；修复把整个调度轮次纳入重试，初始化仅成功后完成，锁冲突不会被当作空队列。新增测试使用真实维护锁和事件，锁释放后原调度器继续工作，实际 HTTP 请求与发生项恰为一次；调度专项 11/11 通过。为处理此缺陷主动停止了第二次全量运行，仅终止该测试树及两子进程，退出码 -15，不把中止记为通过。

## 验证边界

没有 Windows/UOS ARM64 真机验收，也没有对全部历史数据格式完成兼容矩阵。普通手工 ZIP 的 CRC 与清点不能证明压缩工具跨文件时点一致；用户需停止写入后压缩。旧机器加密存储仍依赖原环境的读取能力；保留加密文件不等于跨机器已经解密。

远端模型连接被当前环境 CONNECT 403 阻断；未完成真实远端模型在 DSH 默认沙箱内自主执行全部任务的验收。DSH 本地协议模型夹具不是模型能力成绩。WebRTC 接收的既有 ICE 阻塞保持独立的未通过记录，不能被此次数据和 SDK 结果替代。
