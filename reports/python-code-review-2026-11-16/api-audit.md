最终固定快照 v2 的 `api_flows` 规则 **12 项全部通过，0 失败、0 执行错误、0 跳过**。首次 v1 为 10 项通过、2 项测试口径错误；首错完整保留。两轮产品源码字节相同，仅独立测试夹具修正，不能把这次补救描述为产品首轮全通过或统计稳定性提升。

本报告依据本轮公开 `SKILL.md`、case schema 与源码独立推导，未读取历史审查报告、其他审查者测试文件或真实网关配置。产品实现由开发者修改；本审查只维护 Python 规则、独立测试及本报告。

## 固定业务契约

本地服务绑定 `127.0.0.1` 随机端口，每个测试使用新的临时数据根。登录 JSON 返回合成令牌，后续请求须将它们放进 Cookie；创建返回 201，数字、布尔、null、数组、对象保留类型；查询和修改必须对应本次创建的记录；删除返回无正文的 204 或 201，显式后置查询须确认该记录已不存在。预期先由 fixture 契约定义，再执行请求；不从观察结果反推，不把 HTTP 200 当作全部业务通过。

`extensions.postconditions` 是本轮确认的显式后置关联。它要求同一次冻结运行的真实独立检查；未执行、失败、缺少依赖、observation 或脱离动作依赖的后置不能证明动作业务通过或允许发布。既有 204/205 无正文响应契约保留：最初“所有 204-only 都应未验证”的审查假设已经撤回，不计为缺陷。

## 独立发现与修复复核

| 项目 | 首次依据 | 最终验证 |
| --- | --- | --- |
| 显式 Cookie 引用与保存验证不一致 | 原敏感字段规则仅接受整个值为单个引用，正常 `session={{token}}` 被拒；HTTP fill 支持嵌入引用 | 双 Cookie 模板校验、填充、保存读回及真实冷 HTTP 生命周期通过。修复已进入共享工作区后才运行首次纯函数探针，不声称拥有修前动态失败 |
| 登录 JSON 令牌用于 Cookie 时编译丢失认证 | 独立 Compiler 探针得到后续 `headers={}`、`depends_on=[]`，登录 `extract={}`，`notes=[]` | 原输入现生成提取变量与 producer 依赖，不保存捕获令牌明文；Set-Cookie 来源维持 jar 依赖；多个 JSON 来源同值且无法唯一匹配时明确 unresolved、不猜 producer |
| 完整删除业务需要显式后置约束；201 仅状态的验证语义不一致 | 原保存拒绝缺少正文断言的 201，而执行验证信任任意 assertions；发布只闭合前置依赖 | 201 单步仅状态保留 Unverified；显式后置真实通过后方可发布。204/201 清理完整链、单选动作自动包含后置、失败和未执行后置不发布均通过 |

后置派生结果没有取代原动作 attempt。独立验证检查了真实 HTTP 删除在查空之前，原动作完成时间不晚于后置开始时间，后置完成时间不晚于派生验证开始时间；并通过 `result_evidence` 校验实际执行证据。

## 最终实际覆盖

- 登录 → 创建 201 → 查询 → 修改 → 确认修改 → 删除 204/201 → 查空；正向发布全部合格案例，并按库内默认顺序以另一组输入再次真实执行。
- 返回成功但记录仍存在：查空 Fail，删除与查空不发布。后置缺变量而未发送请求：Blocked，删除不发布。
- 缺前置、空/缺失后置、observation 后置、与动作无依赖关系的后置在 HTTP 变更前拒绝。
- 没有声明后置关联的 201 状态动作不会借后续绿色检查变为业务 Pass。
- 两组带数字、布尔、null、数组和对象的输入均真实执行；同输入 current 证据成立，另一输入不匹配；两个输入范围的 Pass 不能合并发布为同一验证范围。
- 成功链复用后，先确认删除结果在相同输入范围 `result_current=true`；仅修改已发布后置用例的业务断言后，`result_current=false`，原冻结 `result_evidence=true`。该核对未增加一次 HTTP 运行。

## 首错及补救

v1 两处失败分别位于独立测试原第 281、316 行，均把 `results ORDER BY id` 当作 HTTP 顺序；同口径的第 293 行尚未触达。服务端首证明确是 DELETE 后才 GET 查空，七条结果均 Pass 且执行证据有效。`runner.py` 将带后置的动作先暂存，在后置完成后才写入派生结果，所以结果表顺序不等于外部操作顺序。

v1 工作数据按规则清理，精简 JSON 未保存原 attempt 时间，不能声称对 v1 再次读取了这些时间。经根审查者批准，只修独立测试：检查结果编号全集、数量及唯一性，检查完整七步真实方法/路径序列，并保存和验证原动作、后置、派生 attempt 时间。全部发布、复用、输入范围与历史证据断言保留。v2 全部通过，原先被早停挡住的断言均已实际触达。

## 复用方式与证据

```text
python scripts/code_review.py check --rule api_flows
python tests/test_review_api_flows.py --json-output /tmp/api-review-result.json
```

规则在独立 Python 子进程中执行固定契约，只使用隔离临时数据与回环 HTTP，不访问真实网关、读取真实密钥、修改用户数据或安装依赖。失败返回 `rule/severity/path/line/message`，定位到可复核的契约；依据是运行行为，不是源码字符串存在。需要保留详细证据时，在该进程环境设置 `AUTOSKILL_REVIEW_API_RESULT` 为新的输出文件路径；正常检查结束会清理临时数据。

公开精简证据见 [api-audit.json](api-audit.json)，包含快照、测试项、真实运行标识、输入哈希、结果、HTTP 顺序与关键 attempt 时间；不含原始认证。首证和完整执行 JSON 保留在 `/dev/shm/autoskill-pyreview-api-audit/`，文件路径与 SHA-256 已记录在公开证据中。自有规则和测试通过 Ruff。

这些结果证明上述本地 HTTP 契约，不是公网网关、浏览器、生产容量或统计稳定性验收。审查完成后停止修改测试、规则和产品源码。
