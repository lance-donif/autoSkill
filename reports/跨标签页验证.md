# 跨标签页修正与验证

日期：2026-11-12。基线 `449315c`，分支 `fix/sandbox-and-slow-pages`。环境：当前 Linux、Chromium/chromedriver 156.0.8078.79、agent-browser 0.42.0；测试站点为本机受控 HTTP 服务，没有访问或修改真实业务数据。

## 修正前的实际问题

`target="_blank"` 和 `window.open()` 在录制时都能自动跟到子页，但 autoSkill 禁止 `browser tab`，用例也没有保存标签页变化。Playwright 和 Selenium 回放时各自开了两个页面，活动页面仍是父页，验证子页地址失败：两种方式 × 两种引擎，共 4 项失败。原始观察见 `evidence/tabs/before.json`。

## 修正后的行为

- 支持 `browser tab list`、`browser tab t1`、`browser tab new [地址]`、`browser tab close [t2]`。编号在一次录制内稳定且不复用，关闭后返回哪一页也记录下来。
- 将动作引起的新页打开、活动页变化和页面自身关闭写进用例。延迟弹窗在后续读取、断言时也会补记。
- 两种引擎使用同一套标签页状态逻辑；新页缺失、已关闭或无法唯一匹配时报错，不能拿旧页面代替。
- 独立导出脚本嵌入同一套逻辑，不依赖 autoSkill；Playwright 脚本改用显式 browser context，支持创建多个页面。
- Selenium 在下一次用例重置时清理其他窗口，避免上次用例残留窗口影响结果。
- 新页地址匹配提示去掉内嵌凭据、敏感查询参数和 fragment；打开窗口的动作仍由真实点击触发，不拿记录中的地址直接跳转代替。
- 处理页面自身关闭导致 CDP 鼠标事件没有返回的情况：仅在确实观察到活动页消失时记录关闭返回，其他动作错误仍照常报错。

## 实际专项验证

`tests/test_tabs.py` 的真实浏览器覆盖：

1. target blank 链接：子页断言、输入、切回父页、再切回子页验证输入保留、关闭返回父页。
2. window.open：同样的完整往返流程。
3. 250 毫秒后才打开的弹窗：同样的完整往返流程。
4. 子页把输入回传给父页后 window.close，父页断言真实回传值。
5. 手动新建、关闭后台页、关闭原始父页、标签编号不复用；同一驱动重复执行用例，验证重置清理。
6. 一次动作打开两个不同地址窗口，按目的地址匹配并分别切换、断言、关闭。
7. 应当出现的新页未出现：两种引擎都明确失败，保持原页，不误报通过。

前 6 组均经真实录制、Playwright 和 Selenium 回放，并逐个运行两种独立导出脚本。另有步骤格式与敏感 URL 提示过滤验证。专项 9 项全部通过，48.573 秒，见 `specialized-tests.txt`。

另用不能写浏览器控制目录的进程经后台服务完成：建项目 → 录制 → 打开子页 → 断言 → 往返切换 → 关闭返回 → 编译 → 两种引擎回放；1 项通过，8.699 秒，见 `bridge-tests.txt`。这是开发侧模拟受限进程，不是真实 DSH 默认沙箱智能体验收。

## 边界与使用说明

- 更新前录下的跨窗口用例没有标签页变化，需要重新录制。
- 多个新页同时出现且地址无法唯一匹配时会报错，不猜测窗口；普通顺序打开的同地址标签页可用稳定编号切换。
- 关闭最后一页请结束或取消录制。
- 本次没有在 Windows 离线包中重新构建或验证；DSH 模型请求仍受环境代理 403 阻断，没有把智能体任务写成通过。
- 未更新 Release，未合并 main。
