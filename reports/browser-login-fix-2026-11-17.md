# 浏览器显示与人工登录接续修复

用户环境：Windows DSH 插件，GitHub 最新安装包。核对时最新 Release 为 v2.3.0（2026-11-13）；本次修改属于后续源码，不能声称已更新用户电脑上的安装包。

## 已确认的问题

1. v2.3.0 的技能和录制返回信息在发现登录页时要求 `record cancel` 后重新 `record start`。这会关闭原浏览器，不能用于用户手动登录后的接续。
2. 登录 HTTP 接口先读取保存的窗口偏好，可能覆盖显式的 `AUTOSKILL_HEADED=1`。
3. 主分支录制结束后的自动验证未继承启动窗口选择；独立 CLI 进程会重新读取默认值。DSH 父进程残留的隐藏环境值也不能当作用户的新选择。
4. 宿主“后台执行”提示没有区分任务调度与窗口显示。没有发现 JavaScript 按对话轮次自动创建新浏览器会话的代码缺陷，不据此虚构修复。

## 修复行为

- 用户明确显示/隐藏时，技能和宿主提示传递 `--headed` / `--headless` 或 `request.headed`；未指定时保留保存的偏好。
- 人工登录期间保持录制、浏览器与任务绑定；用户回复后先用原会话读取 snapshot，需要时查看真实标签页，继续原任务。
- start/status/snapshot/wait 回执携带任务、浏览器、标签和原窗口模式。重复 start 明确拒绝并引导接续，保留用户正在输入或已经完成的登录。
- 录制保留启动窗口模式，自动验证使用这一模式；旧录制缺少该字段时才读取默认选择。不会改写保存的全局偏好。
- 登录 HTTP 接口采用统一窗口选择优先级。人工认证只证明当前会话可访问，不能冒充已生成可回放的自动登录用例。

## 验证与范围

- 新增开发侧 3 项测试通过：窗口选择组合、登录接口优先级和真实跨 CLI 人工登录接续。
- 独立 8 项验收通过、无跳过：3 条真实 Chromium 流程覆盖人工登录后继续、误发 start 后继续、正在输入时误发 start；另外 5 项核对窗口与队列参数。比较浏览器/控制器进程、CDP 地址、标签及 sessionStorage；补强真实 CDP page target ID 后，3 项浏览器测试再次通过。
- Node 宿主契约 38 项均有通过证据；首轮一项因没有选择 Python 的可选开关跳过，随后显式设置现有解释器单项补验通过。
- Ruff、Biome、7 项项目约定、15 项宿主上下文测试通过。
- 相关录制回归首轮 38 项：35 通过、1 因无 X11 跳过、2 旧断言失败。隔离 HEAD 实际复现相同两项失败；只纠正 Cookie 模板与录制保留的旧预期并保留真实性检查后，2 项复验通过，产品未为迁就测试而修改。

独立首轮验收为 5 通过、3 错误：两个测试过度要求重复 start 必须成功，另一个合成用例缺少必需 start_url。保留首轮日志，仅纠正测试夹具后复验；产品源码未改变。

真实浏览器验证在 Linux 无头环境执行；Windows 默认显示仅做参数契约检查。本轮没有 Windows DSH 真机验收，也未将无头浏览器成功冒充实际可见窗口验证。没有调用远程模型。本次未创建新 Release 或安装包。

可复用测试：`tests/test_manual_login_session.py`、`tests/test_manual_login_contract.py`；完整私有证据保留在本轮 `/dev/shm/autoskill-login-session-fix/` 与独立审查目录，未纳入用户凭据或原始网络数据。
