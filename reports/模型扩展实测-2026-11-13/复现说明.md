# 复现说明

1. 使用 autoSkill c11671395ec4424d98fe5628f61350105a5c6e3d，Python 3.12、Chromium。保留项目原有执行接口。
2. 将“证据/实验源码”中的 `.py.txt` 还原为 `.py`，放在同一外部目录；下载协议与 artifact 清单所列固定权重。解压模型源码包到 extension/vendor 与 extension/sources。
3. 使用证据内 fixtures 固定 HTML；页面版本 a393610d6d42bbbf28c30b6bc4212682a58bbb6c，不访问实时页面。原始下载脚本和项目执行适配器仍在 `/workspace/autoskills-evaluation`。
4. 把本交付 plans 与 plan-manifest 放到 retest-v2，保留原回执；新实验目录改为全新目录，重新冻结协议，不能覆盖旧轮次。安装元数据文件记录的依赖版本，torch 用 CPU wheel。
5. 顺序执行 extension_benchmark.py 的 oracle、plan-direct、main、五个模型命令；--probe 仅用于计分前接口检查。之后另运行 native_dom_benchmark.py freeze/run 进行适配修正补测；两份协议及原始失败都保留。main 凭证从受限本机配置读取，不在交付里；要测新的主模型必须使用自己的有效凭证。
6. 模型任务严格串行；2 线程；统一预热；观察顺序、预算、停止与最终判据见 protocol.json。调用 report_extension.py 生成交付。原调用日志、独立判据、截图和用例映射可交叉复核。

证据不含模型权重或 API 密钥；复用旧计划无需再次调用 API。完整生产离线重放本身不需要小模型；本实验只比较宿主的 AI 决策能力和接法。
