## 2. 做了什么

原仓库有用例存储、校验、导出、调度等周边能力，但没有录制层，页面回放从未真实跑通，仪表盘只能看单个项目。本次重做了核心：

- **录制**：AI 通过 `autoskill browser …` 操作页面，每一步记录多个候选定位方式；断言当场在真实页面上验证，成立才记录；同时捕获接口流量。
- **编译**：一次录制生成 1 条页面用例和它背后的接口用例。令牌变成变量并依赖登录用例，密码变成凭据名称，重复请求复用已有用例。
- **回放**：页面用例可用 Playwright 或 Selenium，接口用例走 HTTP，都不调用模型。可导出 Postman 集合和独立 Python 脚本。
- **前置依赖与登录**：回放任意用例前自动先执行它的前置用例；登录态加密保存在本机并复用，过期自动重登。
- **仪表盘**：四个页面。默认汇总全部项目，项目与时间筛选同时作用于所有数字、图表、列表；每个指标有口径说明并可下钻。
- **分享**：`pack` 打轻量分享包，`pack --full` 打含运行时的完整包，`import` 导入。
- **离线包**：解压即用，不联网、不更新、不上报。

删除了：旧的 `runtime/` 服务、单文件仪表盘、DSH AI 生成与解读、Node 辅助脚本、重复的示例 Skill。按你的要求，仪表盘只负责查看和点运行，不生成用例。

## 5a. 交付后的使用反馈与修正（2026-11-12）

使用者在 DeepSeek Harness 桌面版里让智能体用已安装的技能测试一个公网站点，结论是「实际无法使用」。记录里的问题和对应修改：

| 记录里发生了什么 | 原因 | 修改 |
| --- | --- | --- |
| `project list` 退出码 1，报数据库打不开 | DSH 把智能体的命令放在沙箱里，写不了技能自己的数据目录；未预料的异常直接抛出，不是 JSON | 命令发现自己受限时，自动交给沙箱外的仪表盘进程执行；任何失败都输出 JSON `error`，退出码 2 |
| `record start` 失败：`~/.agent-browser` 不可写；改了用户目录后 Chrome 仍起不来，HTTPS 不通 | 沙箱不允许启动浏览器 | 同上：浏览器由沙箱外的进程启动。浏览器启动失败时的报错说明原因和做法 |
| 给了完全访问权限后，`record start` 报「等待页面加载超时 25 秒」 | 目标页面的脚本下载了 28 秒；浏览器工具的等待固定为 25 秒，无法调整 | 超过这个等待不再算失败，改为对页面本身等待，默认最长 90 秒，可按项目设置（`--page-load`）；回放的页面等待同样改为 90 秒 |
| 重试成功后 snapshot 是空的，随后发现页面跳到了登录页 | 单页应用在加载完成后才画出元素并跳转 | 首个 snapshot 等到页面画出元素；返回里明确写出 `redirected` 和 `needs_login` |

开发侧实际运行过的验证（开发环境，不是离线包，也不是 DSH）：

## 6. 未验证

- **UOS ARM64 真机及其 DSH**：未具备目标机器；不能将 Ubuntu ARM64 原生组装或 x64 开发结果算作 UOS 验收。Linux 包仍依赖系统共享库，旧 UOS 可配置系统 Chromium 与匹配驱动。

- **在 DSH 沙箱里由智能体调用技能**：见 5a。修改后没有在 DSH 里重新试用。
- **DeepSeek Harness 插件**：2026-11-12 在本机的 DSH 桌面版上试装：DSH 接受了插件包并调用了插件入口（安装阶段通过），启用失败，原因是选的是不含运行时的源码目录，且当时离线包里插件和 Skill 分在两个文件夹、需要手动摆放。已改为「解压目录本身就是可安装的插件包」，并用脚本模拟宿主调用确认插件能从包内运行时启动仪表盘。随后在 DSH 桌面版里改选完整包目录重装，启用成功（DSH 操作记录为 applied，仪表盘进程由 DSH 启动并使用包内运行时），使用者确认插件可以启用；面板显示细节没有由开发侧逐项验证。
- **内网真实业务系统**：全部验证使用随附的示例工单系统、TodoMVC 和公开的 todomvc.com。没有在你们的内网系统上运行过。
- **第 5 轮意见的修正效果**：PowerShell 引号等说明已写进 `SKILL.md`，但没有再找新的 AI 试用。
- **显示浏览器窗口（`--headed`）**：在开发环境验证过（命令行和仪表盘都观察到了可见的 Chrome 窗口），没有在离线包里单独验证。
- **零外联**：是进程级连接采样，不是抓包级证明；采样间隔 300 毫秒，极短的连接可能漏掉。
- **其他 Windows 版本**：只在一台 Windows 11 上运行过，Windows 10 没有实测。

## 7. 仍未解决的问题

1. **界面上不能导入分享包**（清单 D6）。只能用命令 `autoskill import`。
2. **定时任务依赖仪表盘进程**。仪表盘没开、电脑休眠时不会触发，也不会补跑。
3. **接口用例的自动断言有强有弱**。响应里没有稳定字段时只校验状态码和大致结构，`record stop` 会提示，但需要人工补强。
4. **带签名、加密或一次性参数的接口**，录出来的接口用例可能无法回放。
5. **验证码、短信、扫码登录**无法自动完成。
6. **需求文档由 AI 自己阅读**。autoSkill 不解析 DOCX / PDF，只提供知识库目录和用例存储。
7. **用例快照会累积**。每次保存用例都会在项目的 `versions/` 下留一份快照，没有清理机制；它们不进分享包。
8. **浏览器只支持 Chromium 内核**。已增加 Linux x64 / ARM64 原生运行时；统信 UOS ARM64 需系统库和浏览器兼容检查，尚未真机验收。
9. **Selenium 独立脚本只用 CSS 定位**。某一步既没有 CSS 也没有测试标识时，该用例不生成 Selenium 脚本，并在导出结果里说明。

## 8. 与原计划的差异

- 趋势图没有叠加通过率折线：两种量纲放在一张图上会用到双纵轴，容易误读。通过率走势改为主指标旁的迷你折线。
- 「在界面里导入需求、生成用例」没有做：你确认了仪表盘只查看和运行，用例由 AI 通过 Skill 录制。
- 离线包不含独立的 Node 运行时和 DSH SDK：去掉 AI 生成功能后不再需要。
