## 2. 做了什么

原仓库有用例存储、校验、导出、调度等周边能力，但没有录制层，页面回放从未真实跑通，仪表盘只能看单个项目。本次重做了核心：

- **录制**：AI 通过 `autoskill browser …` 操作页面，每一步记录多个候选定位方式；断言当场在真实页面上验证，成立才记录；同时捕获接口流量。
- **编译**：一次录制生成 1 条页面用例和它背后的接口用例。令牌变成变量并依赖登录用例，密码变成凭据名称，重复请求复用已有用例。
- **回放**：页面用例可用 Playwright 或 Selenium，接口用例走 HTTP，都不调用模型。可导出 Postman 集合和独立 Python 脚本。
- **前置依赖与登录**：回放任意用例前自动先执行它的前置用例；登录态加密保存在本机并复用，过期自动重登。
- **仪表盘**：四个页面。默认汇总全部项目，项目与时间筛选同时作用于所有数字、图表、列表；每个指标有口径说明并可下钻。
- **分享**：`pack` 打轻量分享包，`pack --full` 打含运行时的完整包，`import` 导入。
- **离线包**：解压即用，不联网、不更新、不上报。

删除了：旧的 `runtime/` 服务、单文件仪表盘、DSH AI 生成与解读、Node 辅助脚本、重复的示例 Skill。按你的要求，仪表盘只负责查看和点运行，不生成用例。

## 4. 真实运行验证

### 回放内核

- 随附 TodoMVC 的 20 条页面用例：Playwright 20/20，Selenium 20/20（Chrome for Testing 157）。原用例里有 2 条断言「刷新后数据保留」，而随附的官方页面使用内存存储、刷新即清空；已改为断言真实行为。证据：`reports/evidence/m2/`。
- 反向验证（两种引擎结论一致）：改错期望 → 失败并给出实际值；元素不存在 → 失败，归类为找不到元素；未授权地址 → 阻塞；首选定位失效 → 用备选定位通过并标注；页面内请求其他主机 → 被拦截。
- 导出的 Postman 集合用 newman 6.2.3 运行：4 个请求、18 条断言、0 失败；不提供凭据时运行失败而不是通过。本机的 apifox-cli 不接受 Postman 格式的本地文件，所以改用 newman。
- 导出的独立脚本：示例项目的 10 份（Playwright 5、Selenium 5）在不加载 autoSkill 的情况下逐个运行通过。

### 前置依赖与登录（示例工单系统）

- 只选「新建工单」一条：自动先登录再执行。再次运行：复用登录态，不再登录。服务端作废会话后：自动重新登录。Selenium 与接口回放共用同一份登录态。
- 登录失败时，依赖它的用例记为阻塞而不是失败；不需要登录的用例照常执行并保持未登录状态。
- 在 `.local` 的全部文件里搜索密码和令牌明文：没有出现。

### 录制

- 用随包的 agent-browser 0.42.0 在示例工单系统上录制「新建工单」：自动登录后录到 4 步、2 条断言，并生成 2 条新接口用例、复用 1 条。回放：Playwright 通过，Selenium 通过，接口通过。
- 项目文件里搜索密码、会话令牌、Cookie：没有出现；原始 HAR 和登录态文件用后即删。

### 仪表盘（真实点击）

- 点击「失败 4」进入列表，列表恰为 4 条。指标与明细相等另有自动化测试覆盖。

用不带任何上下文的 Haiku，只告诉它 Skill 目录和「测试 https://todomvc.com/examples/react/dist/」，其余全靠 `SKILL.md`。每一轮都用当时最新的离线包解压出的全新目录，上一轮的意见修正后再做下一轮。

| 5 | `29c3023` | 3 + 1，回放 4/4；PowerShell 下 `@e11` 未加引号报错，自行改正 | 只核对了它留下的用例文件和运行记录；按你的要求没有再重放 |

复核方式：直接读取它留下的用例文件和运行库，不采信它的自述；再从它的目录里用三条通道各重放一遍，并启动仪表盘确认该项目有数据。截图：`reports/evidence/acceptance-1` 至 `acceptance-4`。

**需要如实说明：** 这个网址是纯前端页面，没有业务接口。每轮的那条接口用例是「读取静态数据 `/learn.json`」，验证文件可访问且结构正常，不是业务接口测试；产品自己也是这样标注的（`api_traffic: static`）。带登录的业务接口录制与回放，由示例工单系统验证。

五轮意见带来的主要修正：命令输出必须是单个 JSON；断言不能用「被断言的文字本身」做定位；静态数据文件不算业务接口；往标题等不可输入的元素里输入文字要拒绝；Git Bash 会把 `/active` 改写成 Windows 路径；录制不能停在空白页；`SKILL.md` 写明每次录制都是全新浏览器、命令要一条一条执行、PowerShell 下 `@e5` 要加引号。

## 6. 未验证

- **DeepSeek Harness 插件**：2026-11-12 在本机的 DSH 桌面版上试装：DSH 接受了插件包并调用了插件入口（安装阶段通过），启用失败，原因是选的是不含运行时的源码目录，且当时离线包里插件和 Skill 分在两个文件夹、需要手动摆放。已改为「解压目录本身就是可安装的插件包」，并用脚本模拟宿主调用确认插件能从包内运行时启动仪表盘。随后在 DSH 桌面版里改选完整包目录重装，启用成功（DSH 操作记录为 applied，仪表盘进程由 DSH 启动并使用包内运行时），使用者确认可用；面板显示细节和智能体调用技能没有由开发侧逐项验证。
- **内网真实业务系统**：全部验证使用随附的示例工单系统、TodoMVC 和公开的 todomvc.com。没有在你们的内网系统上运行过。
- **第 5 轮意见的修正效果**：PowerShell 引号等说明已写进 `SKILL.md`，但没有再找新的 AI 试用。
- **显示浏览器窗口（`--headed`）**：在开发环境验证过（命令行和仪表盘都观察到了可见的 Chrome 窗口），没有在离线包里单独验证。
- **零外联**：是进程级连接采样，不是抓包级证明；采样间隔 300 毫秒，极短的连接可能漏掉。
- **其他 Windows 版本**：只在一台 Windows 11 上运行过，Windows 10 没有实测。

## 7. 仍未解决的问题

1. **界面上不能导入分享包**（清单 D6）。只能用命令 `autoskill import`。
2. **定时任务依赖仪表盘进程**。仪表盘没开、电脑休眠时不会触发，也不会补跑。
3. **接口用例的自动断言有强有弱**。响应里没有稳定字段时只校验状态码和大致结构，`record stop` 会提示，但需要人工补强。
4. **带签名、加密或一次性参数的接口**，录出来的接口用例可能无法回放。
5. **验证码、短信、扫码登录**无法自动完成。
6. **需求文档由 AI 自己阅读**。autoSkill 不解析 DOCX / PDF，只提供知识库目录和用例存储。
7. **用例快照会累积**。每次保存用例都会在项目的 `versions/` 下留一份快照，没有清理机制；它们不进分享包。
8. **只支持 Windows x64 和 Chromium 内核**。
9. **Selenium 独立脚本只用 CSS 定位**。某一步既没有 CSS 也没有测试标识时，该用例不生成 Selenium 脚本，并在导出结果里说明。

## 8. 与原计划的差异

- 趋势图没有叠加通过率折线：两种量纲放在一张图上会用到双纵轴，容易误读。通过率走势改为主指标旁的迷你折线。
- 「在界面里导入需求、生成用例」没有做：你确认了仪表盘只查看和运行，用例由 AI 通过 Skill 录制。
- 离线包不含独立的 Node 运行时和 DSH SDK：去掉 AI 生成功能后不再需要。
