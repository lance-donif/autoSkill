# 用例生成
读取项目分析、知识库、项目 testcase-skill/SKILL.md 和主技能 references/contracts.md。
为每条需求生成正常、异常、边界、必填、权限、状态、交互、一致性场景；兼容性按范围。记录各维度适用/不适用理由，禁止用数量替代充分性。
接口覆盖缺参、类型、边界、无效或过期认证、越权、重复提交、幂等性和响应结构；仅在已确认接口上执行。推导接口留在清单待确认，不编造 URL 或参数。
输入/输出、前置条件、步骤、测试数据引用及可验证预期要具体。每条用例必须关联需求和来源，优先级 P0/P1/P2；预期不明确时记录待确认并阻止执行。
先写标准 JSON，再 validate 和 coverage；区分需求全覆盖与测试执行通过。数据构造与清理步骤显式关联证据。

UI前置条件必须对应真实执行状态，不得把同一段“空列表”复制到依赖已有数据的后续用例。声明场景依赖；供脚本独立执行的用例在 `extensions.automation` 内补充前置数据创建动作和白名单断言，避免依赖上一条用例的浏览器上下文。定位器以实际DOM、已确认源码或可访问性树为依据。无法确认定位器时明确标记尚不可脚本执行，不编造选择器。AI执行结果与脚本执行结果分别记录，不因生成了脚本动作就声称脚本已运行。

save-cases 的输入是扁平对象数组，各对象以kind=ui/api区分类型，不是 {ui:[],api:[]}。用例内容修改必须重新保存并归档旧结果，执行前后不得改定义并沿用原Pass。
