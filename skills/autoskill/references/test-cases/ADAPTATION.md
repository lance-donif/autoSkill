# 来源与离线适配

此 Skill 来自用户上传的 `test-cases.rar`，用户已授权纳入 autoSkill。原始压缩包按原字节保留在 [upstream/test-cases.rar](upstream/test-cases.rar)；[source.json](source.json) 记录原包及其五个原始文件的 SHA-256 和字节数，可解压逐字比较。该清单中的 `source_files` 是原版哈希，不是修改后文件的哈希。原包只供对照，运行时不需要解压它。

本目录完整保留主 Skill、工作簿规则、校验器、宿主元数据与图标，并做以下明确适配：

1. 自动报告由 autoSkill 内核报告渲染器消费冻结任务数据，使用已有包内 Python 和 openpyxl。宿主直接编辑工作簿时可使用其已提供的 `spreadsheets` Skill 或其他已配置工具。无需 Codex 专属运行时、模型密钥或 `@oai/artifact-tool`，也不在运行时安装依赖。
2. 原版用例标识的序号恰好三位；本版接受至少三位，仍从 `001` 连续编号，`999` 后使用 `1000`。不为保持三位而删除用例、截断编号或虚构业务分组。原版校验器会拒绝四位编号，不能将本版通过称为原版逐字校验通过。
3. 原版仅用四种颜色识别四级分组。本版允许真实来源超过四级：在分组 A 格批注中追加独立一行 `autoskill:business-level=<实际正整数深度>`，保留原批注正文，前四级原配色、第五级以后复用灰色。校验器检查注记唯一、层级有上级、颜色相符，按精确深度还原完整路径。不依赖 Excel 只能表达有限层数的大纲级别；注记不授权伪造业务路径。
4. 原版拒绝所有空末级分组。本版仅在 `expected_cases=0`、没有用例行且恰有一个一级项目分组时接受空范围并返回警告，供尚未形成用例的真实阻塞任务交付报告。其他缺例规则保持，空范围不表示覆盖完成或业务通过。
5. 校验器按项目静态检查要求拆分函数、关闭读取的工作簿，并将损坏或非工作簿输入报告为结构校验失败。保留公开 `validate_sheet` 参数和结果结构；除上述兼容扩展外，14 列、必填项、字体、颜色、步骤编号及结果区域保护规则保持。
6. 原版通过“点击搜索/新增/提交”的前缀匹配检查按钮括号，会误伤“点击搜索历史”“点击提交审批”等完整原文。本版只在完整词、可选“按钮”及结束/空白/常见标点边界命中时检查；不能为通过关键词校验而改变实际业务名称。其他按钮仍需对照界面原文复核，校验器不证明按钮真实存在。

## 数据与编号

默认主表为“功能测试用例”，严格采用工作簿规则的 14 列。真实结构不足四级就使用已有结构；未知功能项、编制人或预期依据按主 Skill 的 `【待确认：…】` 规则记录，不能用技术引擎名称、默认登录条件或目标系统的实际回答补造业务事实。

内部用例 ID（例如 `TC-…`）、资产版本、冻结定义及执行身份保持原样。`FT-…` 是工作簿展示标识，记录其与原身份、定义版本和业务路径的对应关系。重排、分组改名或范围变化需要重编号时保留旧新映射，不按行号迁移结果，不用拼音前缀替代内部身份；同名和拼音缩写冲突须按真实归属区分。连续编号针对本表实际范围，不能承诺任意子集都沿用旧序号而仍从 `001` 连续。

同一用例的重复运行、内部重试和多轮对话保留运行/尝试/轮次及独立结果。主表汇总不能把早期 Fail 改写成只有最后一次 Pass；执行明细、来源、截图、备注及长文本可由辅助工作表承载，14 列不是删除证据的理由。模板迁移保留已有执行日期等扩展字段、空单元格的结果颜色、链接、批注和截图关系。结构校验通过不证明业务事实已确认，也不代表测试通过。

## 运行与宿主注册

本目录位于 autoSkill 主 Skill 的 `references/test-cases/`；源码和离线包都按该相对路径解析，不依赖安装绝对路径。DSH 插件将此目录另注册为 `test-cases` 规则 Skill，并以本目录作为 `resourceBase`。通用宿主可从 autoSkill 主 Skill 的相对引用读取。`autoskill-cases` 仍是用户可替换的具体用例数据 Skill，不与这套规则混用。

独立校验使用已配置、带有 openpyxl 的 Python，不启动安装器：

```text
<实际 Python> -X utf8 <本 Skill 目录>/scripts/validate_test_cases.py <工作簿.xlsx> --expected-items <功能项数> --expected-cases <主表用例行数>
```

`--sheet` 指定主表，默认“功能测试用例”；`--exclude-rows` 仅排除明确的模板说明/示例，不排除真实失败行。原有脚本只验证指定工作表的结构与部分样式，不校验拼音语义、需求覆盖、事实正确性、执行证据真实性或全部辅助表。实际交付仍须核对冻结输入与结果、编号映射和保存后的文件；具备渲染工具时检查视觉效果，缺少时明确说明。

DSH 的 `todo_write`、`present` 是宿主能力，由宿主按实际暴露的调用入口使用；本规则 Skill 不内置模型或调用某个宿主 SDK。`present` 成功也不替代工作簿内容校验。普通已授权任务直接执行，无须新增内容审批。
