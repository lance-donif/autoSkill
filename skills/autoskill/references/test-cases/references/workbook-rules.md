# 测试用例工作簿规则

## 业务分组与用例明细

默认四级业务分组，其下为用例明细，计入明细共五层：

| 层级 | 示例 | 填充色 |
|---|---|---|
| 一级：业务域/系统 | 数智运营管理 | `#FFD966` |
| 二级：模块 | 个人工作台 | `#A9D18E` |
| 三级：子模块 | 智能助手 | `#F4B183` |
| 四级：功能项 | 意图识别 | `#BFBFBF` |
| 用例明细 | FT-YTSB-001 | 白底/无填充 |

实际分组不足四级时不补造层级，末级分组承担功能项归属。分组名称按已确认业务结构或模板，只有按文档章节组织时才要求章节原文和序号。

已确认结构超过四级时保留真实完整路径。前四级沿用上表颜色，第五级及以后复用 `#BFBFBF`；分组 A 格批注中使用独立一行 `autoskill:business-level=5` 保存实际正整数层级，已有批注正文保持原样。这是本产品的兼容扩展，未标记的旧表仍按原颜色识别。不要用 Excel 大纲级别代替此标记，也不能为满足模板补造业务层级。

表头灰色 `#BFBFBF`，不合并。分组行按已确认模板合并 `A:L`，M、N 独立；用例行不合并。模板中的“一级～四级”说明行和其他业务示例不计入正式用例数量，新建正式用例时不自动复制示例。

任务在形成用例前阻塞时，可保留表头、一个真实项目一级分组，并在 M 列说明尚未形成用例，不生成假用例。仅当明确传入 `--expected-cases 0`、没有用例行且只有该一级分组时，校验器接受空范围并返回警告。未指定预期数量或预期大于零时仍检查末级功能项是否缺少用例。

## 14 列字段

| 列 | 名称 | 规则 |
|---|---|---|
| A | 用例标识 | 必填、唯一，按末级功能项从 001 连续编号 |
| B | 用例名称 | 必填，仅完整业务分组路径用 `-` 拼接，同组可同名 |
| C | 功能需求追踪 | 必填，精确等于末级功能项名称 |
| D | 测试说明 | 必填，简洁说明本条具体目标，通常以“验证……”开头 |
| E | 前置条件 | 必填，仅列必要条件，普通场景可只写“用户已登录” |
| F | 测试步骤 | 必填，`1. ` 顺序编号、逐项换行，按钮写为 `【界面原文】` |
| G | 预期结果 | 必填，核心结果使用对应步骤编号，允许跳号或从 2 开始 |
| H | 用例编制人 | 必填，沿用用户指定或模板中的实际人员，不写死人名 |
| I | 实际结果 | 按实际执行记录填写，未执行可为空 |
| J | 测试结论 | 保留已有文字和颜色标记，未执行可为空 |
| K | 测试执行人 | 保留原执行人，未执行可为空 |
| L | 验证环境 | 按真实执行环境填写，可为空 |
| M | 备注 | 保留原备注，追加待确认事项，保留原备注；影响执行或判定的缺口同步标在 E/F/G 的受影响位置 |
| N | 截图 | 保留原截图、链接或附件关系，可为空 |

旧表有已填执行日期等默认字段未覆盖的信息时，保留必要扩展列或用户指定位置，不能为凑 14 列丢失记录。新建表默认 14 列；迁移后按表头语义检查字段，不按旧列字母直接覆盖。

## 命名与编号

- A：`FT-<末级功能项拼音首字母>-<至少三位序号>`，每个功能项从 `001` 连续编号，达到 `1000` 时自然扩位，标识全表唯一。原版固定三位，本产品的兼容扩展见 [离线适配说明](../ADAPTATION.md)。
- B：如 `数智运营管理-个人工作台-智能助手-意图识别`，不追加“模型申请流程识别”等本条目标，名称各段去掉章节序号。
- C：如 `意图识别`，与分组原名完全一致。
- D：如 `验证模型申请流程意图识别、流程展示及快捷入口跳转。`
- 层级变化同步更新 B/C；确需重编号时记录旧新标识映射，按该映射保留结果。

## 内容与样式

编写 D–G 列前应用主技能中的“中文用例表达与事实约束”。不以规范措辞改动业务名称、界面原文、验收边界或执行证据。

- 同一业务目标的完整操作链可在一条用例中验证；不同场景、独立控件和可逆操作分别覆盖。多动作、多关键词不等于错误合并。
- 新写上线用例默认粗颗粒度正向范围；旧详细版中的边界、异常、权限等范围按用户授权保留，不套用默认规则删除。
- 步骤只写必要操作或检查动作，不单列被动等待。已知按钮写 `点击【搜索】`，键盘写 `按回车键`，不要把键盘操作改成鼠标点击。
- 预期与步骤编号对应，可省略已验证的公共入口结果。详细场景成立所需的数据、权限、边界参数和断言必须保留。
- **默认字体为宋体**，适用于表头、分组和正文；字号、加粗、边框、对齐参照已确认模板。只有用户另有要求时更换字体。
- 内容使用自动换行，移除为旧列宽插入的句中换行。步骤和条件的逻辑分行、输入数据中的空格或换行不能误删。
- 行高列宽以完整可读为准，不照搬导致截断的旧尺寸，不通过缩小字体强行容纳内容。冻结表头及少量必要标识列，避免冻结过宽。

示例：

| 字段 | 内容 |
|---|---|
| 用例标识 | FT-YTSB-001 |
| 用例名称 | 数智运营管理-个人工作台-智能助手-意图识别 |
| 功能需求追踪 | 意图识别 |
| 测试说明 | 验证模型申请流程意图识别、流程展示及快捷入口跳转。 |
| 前置条件 | 用户已登录 |
| 测试步骤 | 1. 进入“首页-工作台-个人工作台-智能助手”。<br>2. 输入“我想申请模型”，点击【搜索】。<br>3. 点击模型申请流程中的快捷入口。 |
| 预期结果 | 2. 展示模型申请流程及对应快捷入口。<br>3. 跳转至对应流程页面。 |

## 保留测试结果与完整性验证

1. 修改前按用例标识提取执行字段、备注、结果填充色、字体标记、批注、链接和截图锚点，保存基线。
2. 先按表头识别字段，再核对实际内容；颜色可能记在空单元格甚至不相符的旧列名下，需结合原文件和用户说明识别，不推断成通过/不通过文字。
3. 更新名称、层级或行顺序时，历史结果保持与同一用例关联；不要合并多个已执行用例的结论。
4. 导出后用普通工作簿模式读取实际保存的文件，检查 14 个默认表头、必要扩展字段、四级或从简分组、B/C 归属、编号和 A–H 必填项。
5. 用例内容区白底；执行与证据区允许已有结果颜色，不能以“用例行必须全白”为由擦掉结果。
6. 预期编号必须在步骤中存在，但不要求连续。分组和所有有值单元格检查宋体。
7. 逐条核对旧新结果及备注，并保留辅助工作表中仍有效的规则、数据和关联关系。
8. 渲染检查分组、长名称、步骤、预期、备注及结果标记，不能把导出成功当作视觉通过。
