# 测试用例

本目录保留用户提供的测试用例规范，并适配 autoSkill 的离线报告与宿主环境。原始文件、SHA-256 与兼容变化见 [ADAPTATION.md](ADAPTATION.md) 和 [source.json](source.json)；原始压缩包保留在 `upstream/test-cases.rar`。

## 工作原则

- 以用户最新确认的范围、业务结构和模板为准，保留功能项原名，不将不同功能项压缩为一个页面模块。
- 默认编写粗颗粒度正向上线用例。用户要求详细版、异常、边界、权限或回归测试时按明确范围补充；更新已有详细版时保留既有范围，不能用默认正向规则删除旧用例。
- 生成或迁移前读取 [references/workbook-rules.md](references/workbook-rules.md)。autoSkill 自动报告由内核报告渲染器按本规范生成和校验，使用包内运行时，不额外安装依赖。宿主直接编辑 `.xlsx` 时，若提供 `spreadsheets` Skill 则同时使用；否则使用已配置的工作簿工具，保留相同规则与校验边界。
- 修改有执行记录的工作簿时，先按用例标识建立基线，保留测试结果、执行人、日期、备注、截图、链接、批注和结果颜色。不能只检查文字而遗漏空单元格上的结果标记。

## 已确认的默认口径

### 业务层级、名称与标识

- 默认结构是**四级业务分组＋用例明细**：一级业务域/系统、二级模块、三级子模块、四级功能项，其下为用例行。若将明细计入层级，共五层；不得再把用例行称为第四级功能项。
- 示例：`数智运营管理 → 个人工作台 → 智能助手 → 意图识别 → 用例明细`。实际层级不足时按已确认结构从简，不补造中间层。
- 已确认结构超过四级时保留完整路径，不压平或截断；使用工作簿规则说明的分组层级注记，五级以后复用灰色。这是本产品的明确兼容扩展，注记不能代替真实业务来源。
- 分组优先沿用用户确认的业务结构和模板名称。仅在要求按文档章节组织时保留章节原文及序号；不强制所有业务分组带章节号，不擅自改写功能项。
- **用例名称（B 列）**仅由完整业务分组路径用半角 `-` 拼接，例如 `数智运营管理-个人工作台-智能助手-意图识别`。不追加本条测试目标，不拼入 `FT-…` 编号；同组多条允许同名。名称中的章节序号去掉，分组行与 C 列保留已确认的分组名称。
- 名称末段是末级功能项。`智能助手意图输入入口` 可以是第四级功能项，不能仅因名称较具体而从路径删掉。
- **用例标识（A 列）**使用 `FT-<末级功能项拼音首字母>-<至少三位序号>`，如 `FT-YTSB-001`。每个功能项从 `001` 连续编号，达到 `1000` 时自然扩位，标识全表唯一；这是相对原版固定三位的兼容扩展。前缀冲突时采用能区分归属的已确认缩写。
- **功能需求追踪（C 列）**精确等于末级功能项名称。层级改名或用例移动后同步更新名称路径、追踪和编号；已有结果通过旧新标识映射迁移，不能按行号搬运。

### 用例与步骤写法

- **测试说明（D 列）**写本条具体测试目标，通常用简洁的“验证……”句式。替换旧的具体用例名称时，确认目标已保留在测试说明中，不得因同组同名而丢失区分信息。
- **前置条件（E 列）**只列本条必要条件。普通展示/查询用例可仅写“用户已登录”；特定角色、数据、初始状态、边界参数和故障模拟条件确有必要时保留。不默认堆叠配置和实现细节，不删除详细场景成立所必需的条件。
- **粒度**以业务目标判断。同一目标的“输入→展示结果→点击快捷入口跳转”可以是一条完整用例，不按点击次数拆分。不同业务场景、独立筛选控件、独立权限或资源类型分别覆盖；收藏/取消收藏、点赞/取消点赞等可逆操作分别成例。
- 从需求清单提取独立能力并核对覆盖。关键词命中仅用于提醒复核，不能因一条用例出现多个动作或关键词就判定为错误合并。
- **测试步骤（F 列）**用 `1. `、`2. ` 顺序编号，每项换行，按实际操作写，不规定固定步数。进入页面写清已知实际导航路径，输入操作提供具体示例或明确引用前置测试数据。
- **按钮名称使用界面原文，并用 `【】` 标示**：`点击【搜索】`、`点击【新增】`、`点击【提交】`。不得自造按钮文案；键盘动作保留“按回车键”，未知名称的参数化快捷入口可保留“点击入口 i”。
- 不把“等待页面加载完成”“等待结果返回”等被动等待单列为步骤。状态变化用检查动作描述，如“查看演示播放结束后的页面状态”。必要时间点、超时阈值或性能计时仍须保留。
- **预期结果（G 列）**只写本条核心、可观察的结果，通常每个编号一句，不展开无关字段或视觉细节。需求明确的验收点和详细场景必要断言可以保留，不能为简化写法改变测试含义。
- 每项预期使用对应操作步骤的编号，允许仅写 `2.`、`3.` 或跳号，不强制每步都有预期。已由其他用例覆盖的公共入口展示结果可省略；不要省略本条正在测试的入口或页面状态。
- 去掉为旧列宽手工插入的句中换行，使用自动换行排版；保留步骤分行、条件分项、测试输入中的空格和换行等有业务含义的字符。

## 中文用例表达与事实约束

将受控语言原则用于测试内容，不照搬英语词表或句长限制，不宣称符合 ASD-STE100 或国家标准。以下规则内置生效，不依赖另行安装写作 Skill；沿用本技能的用例粒度、表结构和历史记录保护规则。

- **先锁定事实再改写**：记录来源中的数值、单位、精度、范围端点、且/或关系、否定、顺序、权限与“可/应/必须”等约束。不得为润色而换算、四舍五入、纠正疑似笔误或改变承诺强度；疑点写入待确认事项。
- **统一概念名称**：优先使用项目术语表、已确认业务结构和界面原文。同一概念不随意换同义词；认证与授权、超时与失败等不同概念不得合并。不改写功能项原名、按钮文案、接口字段、代码、路径和错误码；别称映射不能覆盖这些原始标识。无法确认是否同义时保留区分并提问。
- **说明具体目标与必要条件**：D 列写本条验证对象和行为；E 列写成立所必需的角色、数据和初始状态。主体在上下文唯一时不重复堆砌；未知主体、角色或页面路径不得猜定。
- **步骤可执行**：F 列每个编号包含一个主要操作，写清已知对象和必要输入；不因拆句而新增用例或丢失条件的作用范围。同一业务目标仍可用多个步骤组成一条用例，不把并行关系改成先后关系。
- **结果可观察**：G 列采用来源支持的页面状态、业务状态、返回值或数据变化，并对应 F 列编号。不只写“正常、正确、成功、符合预期”；有具体含义时直接写出判据。不得擅自补写提示文案、状态码、响应时限、幂等、重试、回滚或恢复机制。
- **区分测试输入与验收标准**：可构造明确标注的示例测试输入，但须符合已知约束，并保持 E/F/G 的引用一致。不得把示例值当作产品默认值、阈值、性能要求或预期行为；边界值由已知需求推导，缺少边界就不编造边界。
- **按含义处理模糊词**：复核“及时、适当、相关、稳定”等词。已有依据就改成具体对象或判据；没有依据则标记缺口，不能擅自量化。不得误改“相关系数”等术语，也不强制所有句子采用同一模板。
- **缺口与冲突可追踪**：用 `【待确认：具体问题及影响】` 标记缺失信息，并在 M 列追加对应事项，保留原备注。影响执行或判定时在 E/F/G 的受影响位置同步标记，将该条视为待确认草稿，不当作可直接执行的完整用例。来源冲突须记录来源位置和差异；没有已知优先级时不自行裁决，不拼出新的组合规则。
- **草稿也保留结构**：待确认内容仍遵守 F/G 的逐项编号要求；G 列不要插入未编号的说明段，缺少判据时写成 `2. 【待确认：该步骤的预期及依据】`。冲突来源与候选规则放在 M 列，不把互斥分支编成同一条已确定流程。复位、开启等独立主要操作分成不同步骤；未确定的操作不得因占位而暗示已授权执行。
- **保护已有证据**：写作整理只调整获授权的用例描述，不润色或补造实际结果、结论、执行人、日期及其他执行证据。新建表缺少真实编制人时用明确待确认标记，不虚构人名；不得将字段非空或格式校验通过当成事实已确认。
- **分开设计与执行**：预期结果表达待验证的要求，不证明功能已经实现或测试已经通过。用户要求假设方案时明确标注假设，不混入已确认需求。

## 工作流

1. **读取输入和基线**：核对需求、原型、最新批注以及模板字段、分组、颜色和合并范围。编辑旧表时按用例标识记录内容与执行证据，区分业务数据、模板示例和辅助表；提取项目术语、事实约束和来源位置。
2. **建立覆盖矩阵**：`完整业务路径 → 末级功能项 → 用例标识 → 用例名称 → 测试说明/覆盖点 → 范围`。明确纳入、排除与待确认事项，不虚构页面、流程或支持能力；记录需求缺口与冲突，区分测试输入和验收判据。
3. **内容确认**：用户要求先确认时，只发结构化草稿，确认后再修改技能或生成工作簿。普通已授权任务直接执行。草稿核对层级、目标、独立能力覆盖、编号、按钮写法和步骤预期对应关系。
4. **编写或迁移**：按上述口径和中文表达规则整理内容。更新详细版时保留独立场景和历史结果；默认规则不构成删例、合并已执行用例或重置测试结论的授权。确需重编号时保留一对一映射。
5. **生成 Excel**：按工作簿规则使用 14 列、四级分组配色和宋体。只合并分组行，不能合并用例行。未执行字段保持未执行状态。
   若任务在形成用例前已阻塞，保留真实项目分组及尚未形成用例的说明，交付零用例范围报告，不造占位用例、不声称覆盖完成；校验时明确传入 `--expected-cases 0`。
6. **验证保存结果**：运行校验器，检查实际导出文件，逐项对照来源复核术语、数值、边界、逻辑和断言依据，再核对结果保留、辅助表和视觉效果。发现差异修复后只重复受影响的检查。

## 运行与验证

所有 bundled 脚本路径从本 `SKILL.md` 所在目录解析。autoSkill 自动报告使用内核提供的导出与校验入口，宿主读取实际文件与 `test_report` 回执；不要另造一份与冻结任务结果无关的表。宿主直接编辑时，在隔离临时目录使用已配置的工作簿工具；若 `spreadsheets` Skill 提供了构建或渲染运行时，按其说明使用。`@oai/artifact-tool` 不是本产品的运行依赖，不要求特定宿主或联网安装，不把机器路径写死在技能中。缺少可用的视觉渲染器时如实说明未完成视觉验证。

若任务确需且已授权使用子 agent，父 agent 先加载工作区依赖并传递实际 Node、Python 和包路径；子 agent 不猜测运行时路径。

```powershell
<Python路径> -X utf8 <Skill目录>/scripts/validate_test_cases.py <workbook.xlsx> --expected-items <数量> --expected-cases <数量>
```

校验器检查字段、实际业务层级、名称路径、C 列追踪、编号、必填内容、宋体、分组颜色、用例行合并以及步骤/预期编号。少于四个业务层级的已确认结构无需另写校验器；模板说明与示例可用 `--exclude-rows 2:6` 显式排除。

结构校验不验证需求事实、语义或业务覆盖。关键词命中仅作复核线索，不能代替逐项对照来源，也不能据此自动删除内容。

还须人工或针对任务检查：

- 中文术语一致，主体和对象可定位，步骤可执行，预期有来源支持的观察判据；数据、边界、否定、条件范围、时序与约束强度未漂移，缺口和冲突已标记。
- 范围和测试含义未丢失，独立功能没有错误合并；已声明的风险场景有归属。
- 按标识逐条比较旧新执行记录、结果颜色、备注和附件，不能把未执行或仅有颜色的记录改写为已通过。
- 字段迁移以表头语义为准，先识别实际结果、测试结论与日期；颜色标记与其用例一起保留，不能让重排导致错配。
- 全表默认宋体；用户另行指定字体时可用 `--font <字体>` 校验。渲染检查可见性、换行、行高和结果标记；不可用时如实说明未完成视觉验证。
- 步骤含被动等待、未括起的已知按钮或预期视觉细节时复核；详细测试必需的内容不能因关键词机械删除。

只交付最终工作簿，构建脚本、基线、检查日志和中间预览留在临时目录。
