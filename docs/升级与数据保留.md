# v2.2.0 升级与数据保留

本次先发布已提交代码和 Apple 风界面。独立自动升级器仍在开发验证，**本包没有 `autoskill upgrade` 命令**。以下是本版本可执行的手动流程，AI 也可使用宿主的文件和进程工具完成它；不能把正在开发的自动流程写成已经可用。

## 需要保留的数据

- 旧安装中的 `autoskill/workspace` 整个目录，包括隐藏的 `.local`，不要只复制 `projects`。项目、用例、知识、原生资产、凭据、登录态、任务、数据库、运行历史和证据都需要保留。
- 若配置了 `AUTOSKILL_WORKSPACE` 或 DSH 插件的 workspace，实际数据在外置目录：完整备份该目录，升级后继续使用原路径。
- `AUTOSKILL_CASE_SKILL`、独立的 `autoskill-cases`、定时任务指定的用例表目录也要备份。
- 保存自定义 `cordis.patch.yml`、运行时的 `runtime-settings.json`、宿主插件设置和自行添加的数据目录。不要用旧 `app`、`plugin` 或 `vendor` 程序覆盖新程序。
- 分享包不包含完整运行历史，不能代替本次安装目录和数据目录备份。

## 用户手动操作

1. 下载匹配操作系统和 CPU 的新 ZIP，核对 Release 中的 SHA-256，解压到一个全新目录。不要解压覆盖旧安装。
2. 让当前录制和测试结束；在 DSH 中停用 autoSkill 插件，关闭独立仪表盘和队列驱动。队列驱动可能独立于仪表盘存活，进程命令中有 `-m autoskill.server.jobs`。按实际命令行确认所属安装后停止它，不要批量结束所有 Python 进程。不要删除定时任务来停止驱动。
3. 确认没有本安装的录制、回放、原生任务或脚本继续写数据后，复制整个旧安装作为备份，并分别备份上面列出的外置目录。SQLite 的数据库与 WAL 等文件必须在停写状态下一起保留。
4. 把旧 `autoskill/workspace` 的完整内容复制到新目录的同名位置，包含隐藏文件。若 workspace 是外置路径或链接，保持原路径配置并核对实际数据。复制独立用例表和需要保留的自定义配置。
5. 为保持 DSH 的 `link:` 地址不变，可把旧安装目录改名为带日期的备份，再将准备好的新目录移到旧地址。若改用新地址，则在 DSH 中更新插件的本地目录。保留旧目录和数据备份。
6. 在新目录执行下面的检查，确认项目列表与旧数据一致，再重新启用 DSH 插件。浏览器刷新后核对 `/api/status` 的 `version` 为 `2.2.0`。

Windows PowerShell，在新安装根目录执行：

```powershell
.\autoskill\autoskill.cmd verify
.\autoskill\autoskill.cmd doctor --launch
.\autoskill\autoskill.cmd project list
```

Linux / UOS，在新安装根目录执行：

```sh
sh setup-linux.sh
./autoskill/autoskill verify
./autoskill/autoskill doctor --launch
./autoskill/autoskill project list
```

有自定义 workspace 时，检查命令也必须使用相同的 `AUTOSKILL_WORKSPACE`。检查返回失败时保留输出，不把文件复制完成视为升级成功。

## 让 AI 操作

可给能够操作本机文件和进程的 AI 这段提示：

> 按新包 docs/升级与数据保留.md，把旧安装 `<旧目录>` 升级到已下载的 `<新包目录>`。先找出实际 workspace、.local、外置用例表和配置，停止本安装的写入进程并完整备份，再准备新目录。保留旧安装，核对全部数据并执行 verify、doctor --launch 和 project list；不要使用本版本不存在的 upgrade 命令，也不要删除旧任务。DSH 插件需要停用或重新启用时，明确告诉我操作哪个插件。

AI 应记录实际目录、备份位置、检查结果和失败原因。如果它只能在受限沙箱中运行且不能操作安装目录，应由本机有权限的宿主或用户执行文件切换，不能只返回“已升级”。

## 恢复与源码安装

检查失败时先停止新进程，保留新目录，再把旧目录恢复到原地址。若新版本已经产生了数据，恢复前还要备份当前 workspace；不能直接用旧快照覆盖新增用例、任务或执行记录。回退后的数据兼容性需要实际检查。

Git 源码安装不使用上述整目录替换：先备份同样的数据和本地改动，停止写入，再 `git fetch` 和 `git pull --ff-only`，按项目依赖说明更新本地环境并执行检查。不能通过重置仓库丢掉未提交修改。

本流程是当前版本的操作说明；尚未据此宣称 Windows、UOS 或默认 DSH 沙箱升级实机通过。
