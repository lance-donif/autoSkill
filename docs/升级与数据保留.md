# 更新程序，保留一个数据文件夹

程序目录与数据目录分离。更新只替换程序，继续选择同一个数据文件夹；不再提供 `upgrade` 命令、独立升级器或升级脚本。

## 数据在哪里

| 平台 | 默认数据目录 |
| --- | --- |
| Windows | `%USERPROFILE%\autoSkill-data`，例如 `C:\Users\juzi4\autoSkill-data` |
| Linux / UOS | `$HOME/autoSkill-data` |

仪表盘「数据管理」和 `autoskill data status` 显示当前实际位置。已有 `AUTOSKILL_WORKSPACE` 或 DSH 插件 `workspace` 配置时，以显式配置为准；安装新版程序不会擅自切换到空目录。要让更新不再涉及数据，选一个安装目录之外的固定位置。

```text
autoSkill-data/
  data-root.json          数据身份、历史位置和明确的路径映射
  projects/               项目、用例、知识、来源、原生资产与版本
  .local/                 完整用户状态：数据库、执行记录、截图、报告、凭据、登录态、
                          用例表、录制草稿、工作流、调度、宿主回执、界面及浏览器设置
```

`.local` 也是需要保留的数据。它不是可随便删除的缓存。完整导出包含凭据与登录态，不过滤成空值。程序自带运行时、系统浏览器、第三方执行器，以及 DSH 自身的模型配置和聊天历史由各自环境管理；它们不属于 autoSkill 数据目录。

## 已有新旧两个程序文件夹：只迁一次旧数据

1. 让旧 autoSkill 的任务结束，在 DSH 停用旧插件或退出旧仪表盘。保留旧目录。
2. 用新程序打开仪表盘的「数据管理」，选择「导入旧数据」，填写旧数据来源和一个**空的目标数据目录**。目录或完整数据 ZIP 都可作为来源。
3. 导入会复制数据并保留原来源。确认返回成功，核对目标路径。导入到另一目录时，当前仪表盘仍显示原来的数据，不会假装已经切换。
4. 将 DSH 插件的 `workspace` 配置改成该目标目录，重新加载插件模块或重启 DSH；通用 Skill 则用 `AUTOSKILL_WORKSPACE` 选择它。
5. 打开「数据管理」核对当前目录，再检查项目、用例、执行明细、截图和报告下载。确认这份数据可用后，旧程序目录由你决定是否清理。

若新程序目录中仍带着旧版标准 `autoskill/workspace`，首次启动可在默认外置根尚未使用时将它复制迁入，同时收纳已知的用例表与运行设置。已有数据根不会被覆盖。跨目录迁入时会登记旧位置，让历史绝对引用指向当前副本，而不是仍存在的旧目录。

原有 Excel、Markdown、截图、冻结输入和原生结果保留原始字节及哈希；不会全文替换路径后重算哈希来冒充原执行。原文件中显示的历史环境、旧来源位置保留为当时的事实。缺失的原证据不会被另一轮结果补造。

## 以后每次更新

1. 记下「数据管理」显示的数据目录，结束任务并退出旧 autoSkill，包括仪表盘和独立后台队列。
2. 将新 Release 解压到新的程序目录，让 DSH 插件或通用 Skill 使用这个新目录，避免旧程序文件混入。
3. 保持 `workspace` 指向同一个数据文件夹，重新加载插件模块或重启 DSH。

不需要再拷贝用例、运行记录或 `.local`。仪表盘资源使用内容版本 URL；重新加载新版插件会打开新页面，无需每次手动清浏览器缓存。磁盘上替换文件不能让已运行的旧插件执行上下文自动更新。

有启用的定时任务时，独立后台队列可以在 DSH 或命令行退出后继续运行。更新前也要退出旧安装的这个进程；如果不便确认，可以结束任务后重启电脑，再启用新包。定时任务定义仍保留在数据目录中，不必删除或重建。

## 整份发给别人

在「数据管理」点击「导出全部数据」，下载生成的 ZIP。也可以关闭 autoSkill 写入后，用文件管理器压缩整个 `autoSkill-data`，包括隐藏文件。复制时保持数据一致；正在变化的数据库与附件不能当作完成的备份。

对方安装匹配平台的程序，将完整数据导入一个空目录，再把该目录设为 `workspace`。也可以直接解压你手工压缩的完整文件夹，把包含 `data-root.json` 的目录设为 `workspace` 后启动，不需要运行迁移或升级脚本。保留 `data-root.json`，这样旧引用能在新位置正确解析。目标已有数据时导入会明确提示，不会悄悄覆盖或合并两份历史。

复制保留历史结果；旧进程号、连接句柄和未确认业务操作不会被当作新机器上可直接继续的任务。运行环境变化后，新执行仍需本机实际可用的工具、浏览器与目标站点；已有历史不会因此被改成新环境执行成功。

旧版依赖 Windows 用户加密或旧密钥的存储，需要在原环境完成读取迁入；保留加密原文件不等于已在另一机器解密。当前明文凭据和保存会话随完整数据一起保留。

## AI 与命令行入口

```text
autoskill data status
autoskill data import <旧数据目录或ZIP> --target <空数据目录>
autoskill data export --out <完整数据.zip>
```

这些是内置数据管理命令，不替换程序、不启动独立升级脚本。AI 应先确认实际数据位置，使用同一份数据，核验回执与真实记录，不能将“导入完成”写成“当前服务已经切换”。导出或迁入失败时保留原目录，修复原因后重试。

`pack` 与 `pack --full` 仍用于项目资产或带运行时的分享，按原合同不包含运行历史；整套数据迁移使用上述数据目录或完整数据 ZIP。

本轮 Linux 验证与 Windows/UOS 实机范围以最终验证报告为准，命令示例不作为未运行平台的通过证据。
