## DSH 入口与本轮验收边界

当前只保留无参数的 `/autoskill-use` 入口，加载当前会话的 autoSkill 技能后再正常对话描述任务；不接受 task/mode，不在入口命令里自行开启模型任务。输入框上方的 TaskDock 已移除，不自动展示任务弹窗；原生工具回执卡默认折叠，需要时展开查看状态、运行和报告，完整页面在仪表盘。

本轮已确认真实 DSH 远程模型、无参技能注入和受限宿主绑定命令。保存隐藏偏好、宿主不含 `AUTOSKILL_HEADED` 强制且存在真实 DISPLAY 时，省略窗口参数的已有 UI 用例回放实际通过，并完成三件任务报告与真实文件交付；其 Chrome 命令行为 headless。首轮录制的 CDP 启动失败保留原记录，随后以最小启动参数修复并完成真实录制、保存及回放专项；不将早期失败改写成首轮通过。

真实 DSH iframe 的12页在桌面浅色、桌面深色、窄屏浅色下共36个视图均已加载且没有脚本异常。首轮项目与执行记录窄屏溢出已修复，复测36视图均无根页面溢出。冻结源码的原生自测、公开站点功能设计与最终任务结论见[本轮 DSH 真实验收](../reports/DSH真实验收.md)；普通浏览器专项、真实外层 iframe、远程模型调度和原生测试结果分别记录，不互相冒充。

人工录制的每次 click、工作流租约、judge 心跳等仍属于 AI/执行器协议；人用页面提供任务、来源、设计、配置、结果与证据，不逐条复制这些内部协议按钮。

## 基线结论

存在与压测相同的“内核已有能力，但人用页面尚未形成完整操作流程”的情况。优先补齐原生资产管理、原生执行报告、需求工作流审阅和非回放定时任务。多轮对话、运行诊断、知识查看、项目分享也缺少相应页面。

现有独立仪表盘提供仪表盘、项目与用例、执行记录、定时任务、数据管理五个页面。DSH 在嵌入仪表盘外，还提供本会话任务面板、工具回执卡、取消执行及报告获取；不能将这些已有能力记为完全缺失。

## 基线：原建议补齐顺序

1. 完成本次已有用例压测入口、负载配置、进度、取消与真实指标展示。
2. 建立原生资产入口，并让原生报告正确展示性能、多轮质量与附件；调度页按回放/原生/AI 维护提供不同字段，避免误编辑其他任务类型。
3. 建立需求、覆盖、候选变更和业务结论审阅页。保留 AI 驱动执行，人可以检查来源、预期、失败及变更依据。
4. 在同一资产与报告流程中补多轮构建、质量审阅；再补诊断、知识和项目分享。

不建议逐个 CLI 命令机械生成按钮。`workflow next/submit/heartbeat`、`judge next/submit/heartbeat`、`browser click`、bridge/dispatcher 等是宿主协议或执行细节，应该继续由智能体与内核完成；页面面向用户提供任务入口、可编辑业务配置、明确进度、证据和失败原因。
