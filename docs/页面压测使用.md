# 在页面对已有用例进行压测

本页说明仪表盘中的「压测」功能。它复用已有页面和接口用例、原断言以及前置依赖，按指定并发重复执行用例组。

## 打开入口

启动当前程序的仪表盘，浏览器访问 <http://127.0.0.1:8787>，选择侧边栏「压测」。

```bat
autoskill\autoskill.cmd dashboard
```

Linux 完整包在包目录运行 `./autoskill/autoskill dashboard`。源码环境装好依赖后，在仓库根目录运行：

```bash
PYTHONPATH=skills/autoskill/app python -m autoskill dashboard --port 8787
```

源码改动不会自动更新已下载的完整包，也不会自动发布 GitHub Release。需要使用包含本功能的程序；更换程序后重新启动仪表盘，DSH 用户重新加载插件模块或重启宿主，继续使用原数据目录。

## 选择已有用例

「压测」页面可选择项目及已有用例。「项目与用例」页面也提供单条、勾选所选和整个项目的压测入口，打开配置时保留对应选择。

先用普通回放核对业务断言与依赖，再配置负载。已有断言保持原预期；录制时观察到的响应不能自动充当独立业务预期。缺少可执行步骤、前置或运行依赖时，按页面和运行结果中的原因处理。

## 配置负载并启动

| 参数 | 含义 |
| --- | --- |
| 并发用户数 | 同一压测任务中同时执行用例组的虚拟用户数量 |
| 迭代次数 | 整组所选用例执行多少次，每次按依赖顺序运行 |
| 渐增时间（秒） | 分批启动虚拟用户的时间；0 表示立即启动 |

例如，选择 2 条用例，并发数为 3、迭代次数为 6，计划目标是 12 条次，最多同时执行 3 组；为满足依赖而额外执行的前置用例不计入目标数。迭代次数不会再乘以并发数。

页面用例沿用顶部「回放设置」中的引擎、显示浏览器窗口和浏览器选择；接口用例使用 HTTP。点击「开始压测」后进入运行详情，离开详情页后仍可从压测历史重新打开。

每次迭代从空 Cookie、独立变量和独立浏览器登录态开始，不复用或写回本机共享登录态；同一组内的依赖与变量传递继续生效。压测参数与用例内容按启动时的版本保存，后续修改当前用例不会改写这次运行的输入与结果。

## 查看进度、结果和停止

详情展示计划与已完成条次、执行通过、失败、阻塞和尚未执行数量。指标口径如下：

| 指标 | 口径 |
| --- | --- |
| 用例吞吐量 | 已完成目标条次 ÷ 实际墙钟耗时，单位为用例/秒；包括失败和阻塞，不含前置 |
| 失败与阻塞率 | （失败条次 + 阻塞条次）÷ 已完成目标条次；尚未执行单独显示 |
| P50/P95/P99 | 真正发送请求或执行页面步骤的目标用例耗时分位数，单位为毫秒；前置及未发起的阻塞目标不计入延迟样本 |
| 接口请求发送数 | 已发起的接口用例请求，包含前置，不统计页面内部的网络请求 |

用例吞吐量不是 HTTP QPS。页面用例耗时包括完整场景的浏览器操作和断言等待。查看逐次结果可核对原断言的期望与实际；执行通过仍需结合业务验证结论，没有独立业务断言时不能据此宣称业务正确。

点击「停止压测」后，不再启动新的用例，正在执行的调用按执行器的取消和超时机制结束。已产生的结果与失败证据保留，尚未完成的目标单独显示，不合并成通过。详情也可「再次压测」或导出任务报告。

## 与原生压测资产的关系

| 测试对象 | 使用方式 |
| --- | --- |
| 已有 autoSkill 页面、接口用例 | 使用本文的页面入口，复用用例与依赖执行 |
| 已有 JMeter `.jmx` 计划 | 在「原生资产」导入并运行，或使用 `asset import --engine jmeter`、`native run`；线程、循环等负载参数由计划配置，本机需安装 Java 和 JMeter |
| HTTP、SSE、WebSocket 多轮对话资产 | 在「多轮对话」导入捕获并构建资产，再配置 `load` 执行；也可继续使用 `conversation build`、`native run`。需要宿主判定时保持宿主处理判定队列 |

「压测」页面复用已有 autoSkill 用例；原生资产页面沿用 JMeter、对话等原引擎的负载参数，运行结果进入原生报告。原生命令见[命令参考](../skills/autoskill/references/commands.md#原生资产会话捕获与宿主判定)。

浏览器用例产生的是完整业务场景负载，包含浏览器操作和断言等待；需要大量协议请求时可使用 JMeter。具体容量需在实际环境测量，本地合成站点的验收结果只证明功能链路。
