# autoSkill 需求与验收清单

状态标记：☐ 未开始 · ◐ 进行中 · ☑ 已由真实运行验证（附证据路径）。没有真实运行证据的条目不得标 ☑。

来源：2026-11-12 用户确认的计划。里程碑与边界见文末。每项下方的「验证」说明是怎么确认的；完整证据见 `reports/交付验证报告.md`。


**A 录制与回放（核心）**
- ☑ **A1** AI 通过 `autoskill browser …` 操作页面，每一步自动记录：动作、多候选稳定定位器（testid / role+name / label / placeholder / css）、前后 URL、是否成功。
  - 验证：真实录制实测；`tests/test_recorder.py`
- ☑ **A2** 同一会话同步录制接口（HAR）；落盘前剥离 Cookie/Authorization/Token，密码类输入替换为凭据变量引用。
  - 验证：录制后在项目文件中搜索密码、令牌、Cookie 均未出现；原始 HAR 用后即删
- ☑ **A3** `autoskill record stop` 一次产出 UI 回放用例 + 接口回放用例（状态码、推断的响应结构、稳定字段断言、前后请求变量关联）。页面没有业务接口时，如实产出「页面与资源可用性」类接口用例并标注类别，不伪装成业务接口。
  - 验证：示例工单系统录出业务接口用例；TodoMVC 录出 `static` 类并如实标注
- ☑ **A4** 同一份 UI 用例可用 Playwright 和 Selenium 两种引擎回放，纯 Python，不调用任何模型。
  - 验证：TodoMVC 20 条在 Playwright 与 Selenium 上各 20/20，`reports/evidence/m2/`
- ☑ **A5** 接口用例可独立 HTTP 回放，可导出 Postman Collection v2.1 + Environment（含 `pm.test` 断言，登录请求在前、令牌自动传递）。
  - 验证：导出集合用 newman 6.2.3 跑通：4 请求 18 断言 0 失败；缺凭据时失败而非通过
- ☑ **A6** 可导出不依赖 autoSkill 的独立脚本（Playwright `.py` / Selenium `.py`）。
  - 验证：示例项目导出的 10 份独立脚本在不加载 autoSkill 的情况下逐个运行通过

**B 前置依赖与登录态（新增）**
- ☑ **B1** 用例可声明前置用例；项目可定义「登录方式」＝一条登录用例 + 登录态有效性检查。录制时如果用了已保存的登录态，或接口请求带了认证信息，编译器自动给用例挂上对应依赖。
  - 验证：`tests/test_recorder.py`、`tests/test_runner.py`
- ☑ **B2** 运行任意用例（单条、批量、定时）前自动解析依赖并按顺序执行；同一次运行里前置只跑一次；前置失败时后续用例标「阻塞：前置用例失败」，不记为失败。
  - 验证：只选一条用例，自动先登录；前置失败时依赖项记为阻塞。`tests/test_runner.py`
- ☑ **B3** 登录成功后把登录态存在本机（浏览器 Cookie/本地存储，以及接口用的 Cookie 和令牌变量），UI 和接口回放共用；有效则直接复用，失效自动重新登录一次。
  - 验证：Playwright、Selenium、HTTP 共用同一份登录态；服务端作废会话后自动重登
- ☑ **B4** 登录态和账号密码值只存本机、Windows DPAPI 加密，不进用例、报告、日志、导出包。
  - 验证：DPAPI 加密；在 `.local` 全部文件中搜索密码与令牌明文均未出现
- ☑ **B5** AI 第一步执行 `autoskill context <项目>`，一次拿到：知识库要点、登录方式与对应登录用例、当前登录态是否有效、已有用例、授权地址。`autoskill login <项目>` 无需 AI 即可完成登录。用户不必提醒「先登录」。
  - 验证：`autoskill context`、`autoskill login` 实测（首次、复用、强制）

**C 项目、Skill 与分享**
- ☑ **C1** 项目有名称与分类；每个项目是一个 Skill 目录：`SKILL.md` + 知识库 + 用例 + 回放脚本 + Postman 集合 + 登录方式定义。
  - 验证：每个项目生成自己的 `SKILL.md`；回放脚本与 Postman 集合按需导出到项目目录
- ☑ **C2** 工作区默认放在 Skill 目录内，压缩整个 Skill 目录即带走全部用例和知识库；本机私有数据（登录态、密码值、运行记录、截图）单独放在 `.local/`，打包时自动排除。
  - 验证：工作区在 Skill 目录内；`.local` 不进分享包、不进 Git
- ☑ **C3** `autoskill pack` 一条命令出分享包：轻量包（仅 Skill + 用例 + 知识库，几 MB）或完整包（含运行时）；`autoskill import` 导入别人给的包并合并项目。
  - 验证：`pack`、`pack --full`、`import` 实测：新工作区导入后设置凭据即可回放
- ☑ **C4** 密码默认不随包分发：对方首次使用时 `context` 会列出缺哪些凭据变量，设置一次即可。团队共用测试账号时可加 `--include-secrets`，用口令加密后随包带走。
  - 验证：口令正确才能恢复凭据，错误口令被拒绝。`tests/test_server.py`

**D 仪表盘**
- ☑ **D1** 默认「全部项目」汇总；项目筛选器可切换单个项目；时间范围（今天 / 近7天 / 近30天 / 自定义）与项目筛选**共同作用于所有卡片、图表、执行记录、失败列表**。
  - 验证：真实点击验证：切到空项目后全部指标、图表、列表同步为空
- ☑ **D2** 始终显示当前筛选范围，一键重置；筛选写入 URL，刷新不丢。
  - 验证：筛选写入网址，刷新后保持；重置按钮回到「全部项目 · 近 7 天」
- ☑ **D3** 指标与口径（每个指标旁带「口径」说明）：
  - 验证：每个指标旁有口径说明。与计划的差异：通过率走势单独画成迷你折线，不与条次柱状图共用一张图（避免双纵轴误导）
  - 用例总数＝截至范围结束时处于活动状态的用例数；副标：范围内新增、UI/接口拆分
  - 执行次数＝范围内开始的运行次数；副标：用例执行条次
  - 通过率＝通过条次 ÷（通过＋失败）条次；阻塞/未执行不进分母，单独展示
  - 失败 / 阻塞＝范围内结果为失败 / 阻塞的用例执行条次；可切「仅看当前仍失败」
  - 执行趋势＝按日（范围≤1天按小时）堆叠通过/失败/阻塞条次 + 通过率折线
  - 定时任务状态＝筛选项目内启用/暂停数、下次执行、范围内触发次数与最近一次结果
- ☑ **D4** 点击任一指标进入**相同筛选条件**下的明细。
  - 验证：点击「失败 4」进入列表，列表恰为 4 条
- ☑ **D5** 统计由服务端 SQL 聚合，与明细数字逐项相等（有自动化测试校验）。
  - 验证：`tests/test_server.py::MetricsTests`
- ◐ **D6** 无数据时给出明确引导：加载示例项目 / 复制一句话指令交给 AI 开始录制 / 导入分享包。
  - 验证：首次使用提供「加载示例项目」和「复制给 AI 的指令」；导入分享包目前只有命令行（`autoskill import`），界面上没有入口

## 已知边界

- **TodoMVC React 是纯前端页面，没有业务接口**（已下载其页面与脚本核对：主程序里没有任何接口调用，只有辅助脚本 `base.js` 含 XMLHttpRequest，是否真的发请求以录制时实际观察为准）。所以在这个站点上「接口用例」只能是页面与静态资源请求的可用性检查——是真实 HTTP、可回放，但不是业务接口，界面和报告里会这样标注。带登录和前后依赖的业务接口回放，由示例工单系统证明。
- M9 需要访问公网上的 todomvc.com，这一步不是离线验证；离线能力由 M8 用包内示例系统单独证明。
- 本机没有 DSH 宿主：插件加载只能做到契约测试，无法证明在真实 DSH 里显示正常。
- 「零外联」只能证明到进程连接采样层面；抓包级证明需要管理员权限，不擅自操作。
- 接口变量关联是启发式的；带签名/加密的请求会标记「需人工确认」，不伪装成可回放。
- 登录需要验证码、短信或扫码时无法无人值守：首次由人完成一次登录，登录态存下后复用，过期时任务标阻塞并提示。
- Release 附件是否公开取决于仓库可见性；完整包只含开源运行时及其许可证。分享包里有你的用例和知识库，发给谁由你决定。
