## 本版变化

- 在 DSH 对话中设计用例时，每个独立验收目标占 14 列设计表的一行。例如，打开页面、定位流程图并截图交付属于同一行，各步都有对应的编号预期。目标数明确时，技能通过 `plan write` 的 `--expected-cases` 在写表前核对行数，数量不符会提示期望数和实际数。原有命令写法仍可使用。
- 并行录制的结果回填到各自的原任务和设计行。可从运行的发布回执核对哪些用例已入库，在执行详情和离线 HTML 中按每次重试看步骤、断言和截图。设计报告导出中断时，用 `autoskill task-report <报告编号> --retry` 可从原快照恢复 Excel、简报和 Bug 清单。
- 新录制的全局按键在 Playwright 和 Selenium 回放时都发给浏览器当前焦点，方向键选择、回车确认会遵循页面的实际行为。已保存的带定位按键仍按原目标执行。复选框和开关按实际选中状态检查，同名但角色不同的控件在页面重排后也能区分。
- 覆盖导入项目分享包时保留本机已交付的历史报告。重新导出分享包遇到错误时，上次完整的 ZIP 仍可使用。Linux 录制和回放可在较长的临时目录下启动浏览器。
- 常用 CLI 命令启动更快，查看执行历史时减少重复读取证据。压测报告先显示图表，展开时再生成明细行。目标请求即使返回 HTTP 200，只要关联的后置断言失败，该样本就计为失败。

候选源码在 Linux x64 通过 CLI、本机 HTTP 桥和 Chromium 仪表盘回归。Windows Server 上的 PowerShell 5.1、PowerShell 7 录制与报告测试复跑通过。Windows 11 上 DSH Desktop 0.2.2-rc.5 的原生文件卡仍待现场验收。[候选版验证记录](https://github.com/lance-donif/autoSkill/actions/runs/44754402970) · [问题 #4](https://github.com/lance-donif/autoSkill/issues/4)
